# 第一阶段 iOS 原生移植记录

基线：`docs/第一阶段产品规则确认单_2026-09-09.md`、小程序 `app.json` / `services/api.js` 与现行后端控制器。2026-09-10 开始迁移。

## 技术与范围

- 在现有 iOS 工程内继续实现，Swift + SwiftUI；表单、导航、弹窗、照片选择使用系统组件，无 WebView、Flutter 或小程序运行容器。
- iOS 16+，iPhone/iPad。后端沿用现有 API，不复制数据库和业务事务。
- 第一阶段仅到店、线下收款。客户端不提供线上支付、线上退款或上门入口。
- 金额输入按十进制解析为分后校验，确认/完成接口按其契约转为元。
- 本记录区分代码实现、编译/单元测试和真实端到端验收。工程能编译不等于全部功能移植完成。

## 本次实现与修复

| 范围 | 实现 |
|---|---|
| 请求与登录 | 角色隔离、每请求最多一次刷新、并发刷新按角色合并并传播失败、普通网络故障保留会话、恢复失败可重试、切换账号清理旧凭证、密码重置 |
| 双角色 | 客户密码登录时尝试获取同账号美甲师凭证；美甲师使用已认证 switch-to-client 接口获取客户身份；已有双角色凭证可来回切换。未取得美甲师凭证时提示先登录，不冒用客户 token |
| 客户首页 | 后端推荐作品、默认美甲师预约、最新预约详情；移除旧静态首页展示 |
| 绑定 | 客户绑定/待审核计数、5 位上限、邀请码查找、申请、撤回、解绑、默认美甲师；美甲师通过/拒绝申请 |
| 预约申请 | 原生门店和服务选择、自定义需求、北京时间、现行 API 字段、稳定幂等键；修改申请内容后更新键 |
| 美甲师预约 | 按状态提供报价/最终确认/取消/完成操作；报价日期时间时长、总价与定金、线下收款、取消退款记录、实际服务记录、已完成订单关联作品草稿 |
| 客户预约 | 接受/拒绝报价、取消预约、文字评分评价；变更后回读 |
| 作品 | 图片选择上传、封面、草稿、编辑、审核提交、显示/隐藏、置顶、主页精选、二次确认删除、操作后刷新 |
| 客户首页推荐 | 审核/可见/公开/封面/归档资格检查，3 位上限，满额替换和取消确认，expectedWorkIds 并发校验 |
| 客户资料 | 收藏、点赞、编辑资料、账号注销申请/状态/阻止原因/撤回 |
| 服务项目 | 公开字符串 ID、价格与 durationMinutes、分类、添加/编辑/启停/删除 |
| 工作台 | 实际订单统计与今日预约，绑定审批和经营工具导航 |
| 聊天 | 修正会话/消息响应模型、已读参数和发送响应，原生图片发送、失败保留文本、页面可见时定时刷新 |
| 反馈和通知 | 反馈真实提交成功才提示成功；通知读取系统授权状态，不把本地开关当成服务端已启用 |
| 工程验证 | 新增 XCTest target，金额边界、密码规则、请求角色与方法、401 不无限重试、列表封装、作品解析和日期格式测试 |

## 本地验证方法

```sh
xcodegen generate
xcodebuild -project NailBook.xcodeproj -scheme NailBook \
  -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build
xcodebuild -project NailBook.xcodeproj -scheme NailBook \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' CODE_SIGNING_ALLOWED=NO test
```

联调时在 Scheme 的 Environment Variables 中设置 `NAILBOOK_API_URL`（带 `/api`）。默认仍为现有生产 API；自动化契约测试注入 URLProtocol，使用 `nailbook.invalid`，不对生产写入。需要 HTTP 测试服务时应使用专用 Debug ATS 配置或 HTTPS，不为正式构建全局关闭 ATS。

不在代码或文档中存储登录密码、短信验证码、生产 token 或签名证书。
