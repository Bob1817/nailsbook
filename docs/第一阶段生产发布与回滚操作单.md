## 4. 发布命令

以下命令在 ECS 的 `/opt/nailbook` 执行。先确认工作树仅包含已批准的生产配置。

```bash
git fetch origin --tags
git checkout v1.0.0-rc.1

BACKUP_DIR=/opt/nailbook/backups \
DB_PATH=/var/lib/docker/volumes/nailbook_backend_db/_data/prod.db \
./deploy/backup-db.sh

docker compose pull backend admin-web
docker compose run --rm backend npx prisma migrate status
docker compose run --rm backend npx prisma migrate deploy
docker compose run --rm nginx nginx -t

BACKEND_IMAGE=ghcr.io/bob1817/nailsbook-backend:sha-13ae1398863a2cd0e3cf58490c111044f1e27bd3 \
ADMIN_WEB_IMAGE=ghcr.io/bob1817/nailsbook-admin-web:sha-13ae1398863a2cd0e3cf58490c111044f1e27bd3 \
docker compose up -d backend admin-web nginx
```

将两项镜像变量写入服务器受控的根目录 `.env` 后再次运行 `docker compose up -d backend admin-web nginx`，确保重启后不会退回 `latest`。

- [ ] 公网响应包含 HSTS、`X-Content-Type-Options`、`X-Frame-Options` 和 `Referrer-Policy`。
- [ ] 观察 15 分钟：无持续 5xx、容器重启、磁盘异常或明显延迟上升。

## 6. 回滚触发条件

出现下列任一情况，由回滚决策人立即停止写入并回滚：登录普遍失败、预约或金额数据错误、迁移失败、持续 5xx、容器反复重启、上传不可用且无快速恢复方案。

## 7. 回滚命令模板

```bash
docker compose stop backend admin-web

# 将 <OLD_...> 替换为发布前记录的不可变镜像，将 <BACKUP_DB> 替换为已验证快照。
BACKEND_IMAGE=<OLD_BACKEND_IMAGE> \
ADMIN_WEB_IMAGE=<OLD_ADMIN_IMAGE> \
docker compose up -d backend admin-web
```

若本次 migration 产生了不兼容写入，再停止 Backend，将 `<BACKUP_DB>` 通过 SQLite backup API 恢复到生产数据库路径，然后启动旧 Backend。不得在运行中的 SQLite 数据库上直接覆盖文件。

回滚后执行 API 健康、管理登录、公共作品和预约只读冒烟，并记录恢复时间、数据恢复点和受影响用户。
