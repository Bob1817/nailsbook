# NailBook 首期上线资质规避改动需求文档

**文档版本：v1.0**
**编写日期：2026-08-19**
**需求来源：微信小程序上线资质合规评估**
**状态：待评审**

---

## 一、背景与目标

### 1.1 问题背景

NailBook 项目定位为美甲预约 SaaS 平台，当前功能已接近 MVP 完成（综合完成度 89%）。但在微信小程序上线合规评估中发现，有两项资质在首期版本中几乎无法取得：

| 资质名称 | 获取难度 | 根因 |
|---------|---------|------|
| 上门美甲服务试点主体资格 | 极高 | 微信平台规定「上门美容、美甲」类目仅对试点主体开放准入，新主体无法申请 |
| ICP 许可证 + EDI 许可证 | 极高 | 涉及第三方交易平台撮合 + 虚拟商品在线付费，需持证经营；初创公司短期内无法取得 |

### 1.2 改动目标

通过产品功能的**有限让步**，绕开上述两项资质要求，使首期版本能够以**最低合规风险**通过微信小程序审核并上线。核心策略：

1. **移除上门美甲服务** → 规避「上门美容、美甲」类目准入限制
2. **订阅套餐去价格化** → 规避虚拟商品在线付费触发的 ICP/EDI 许可证要求
3. **定金/尾款线下化** → 规避虚拟支付许可证要求（已有降级机制，几乎零改动）

### 1.3 产品定位调整

| 维度 | 原定位 | 调整后定位 |
|------|--------|-----------|
| 产品形态 | 美甲预约 SaaS 平台 | 美甲师经营管理工具 |
| 服务模式 | 到店 + 上门双模式 | 仅到店服务 |
| 订阅付费 | 在线套餐支付 | 人工确认升级（客服联系） |
| 定金/尾款 | 在线微信支付 | 线下转账（微信支付能力暂关闭） |

> **关键说明：** 以上均为**首期版本的有限让步**，后续取得相关资质后可逐步恢复完整功能。代码层面的改动保持可逆性，以 `feature flag` 或条件判断方式实现，便于后续恢复。

### REQ-03：定金/尾款支付线下化（P0）

**规避资质：** 虚拟支付许可证

**需求描述：** 定金和尾款的在线微信支付能力在首期版本关闭，支付按钮通过已有的 `wechatPayAvailable` flag 自动隐藏。客户与美甲师之间通过线下转账完成定金/尾款支付。

**涉及文件：** `client-wxapp/pages/client/order-detail/index.js`

| 编号 | 改动点 | 当前代码 | 目标状态 |
|------|--------|---------|---------|
| 3.1a | 支付能力开关 | `capabilities.wechatPay` → `wechatPayAvailable`（L48-50） | 后端 `wechatPay` 能力返回 `false`，前端自动隐藏支付按钮 |
| 3.1b | 支付按钮显示逻辑 | `wechatPayAvailable && ... payDeposit/payFinal` 条件判断（L26-27） | 无需改动 — flag 为 false 时按钮自动不显示 |
| 3.1c | 支付流程处理 | `startPayment` 方法，`channelReady` 为 false 时弹提示（L150-180） | 无需改动 — `channelReady` 为 false 时已有降级提示 |

> **说明：** 此需求几乎零代码改动，后端配置 `wechatPay` 能力为 `false` 即可。`channel_pending` 状态已作为支付单的中间态预留，后续资质完成后恢复 flag 即可启用。

### 4.2 不受影响的功能

以下功能不受本次改动影响，保持现有实现：

- 到店美甲服务全流程（预约 → 确认 → 进行中 → 完成）
- WebSocket 实时聊天
- 作品集管理（上传/编辑/删除/可见性）
- 评论/点赞/收藏
- 超管后台 RBAC 权限系统
- 操作审计日志
- 系统自动订单状态转换（Cron）
- 到店提醒通知

### 4.3 可逆性说明

所有改动均保持可逆性：

- **上门服务移除**：通过 `serviceType` 条件判断实现，后续恢复上门功能时重新启用 `homeService` 逻辑即可
- **订阅去价格化**：仅 WXML 层展示改动，数据结构不变，恢复价格展示只需还原模板
- **支付线下化**：`wechatPayAvailable` flag 已是配置化控制，恢复在线支付只需后端开启 flag

## 六、约束与假设

1. **后端 API 兼容**：后端接口仍保留 `homeService`、`addressId` 等字段，前端不传即可，后端不做破坏性改动
2. **数据兼容**：已存在的上门服务历史订单数据保留，仅前端不展示 `pending_home` 状态
3. **多端一致性**：本次改动仅涉及微信小程序端（`client-wxapp`），Web 端（`client-frontend` / `technician-frontend`）不受影响
4. **后续恢复路径**：取得相关资质后，按逆序恢复功能即可
