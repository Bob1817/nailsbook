### 3.1 获取 AppID / AppSecret

| 项 | 说明 |
|----|------|
| 入口 | 开发者平台 → 我的业务与服务 → 服务号 → 基础信息 → **开发密钥** |

- 长期不用可「冻结」（返回 40243），需要时解冻；冻结/解冻需 10 分钟生效。

### 3.2 API IP 白名单（不做会报 40164）

| 项 | 值 |
|----|-----|
| 入口 | 开发者平台 → 服务号 → 基础信息 → 开发密钥 → API IP 白名单 |
| 必填 IP | `47.96.159.106`（ECS 出口 IP） |
| 格式 | 支持具体 IP 与 IP 段（如 `47.96.159.106` 或 `47.96.159.0/24`），**不支持** `47.96.159.*`，**不支持**带端口 |

### 3.3 域名配置（3 类域名，规则不同，逐个配）

#### 3.3.1 三类域名对比

| 项 | JS 接口安全域名 | 网页授权域名 | 业务域名 |
|----|------------------|--------------|----------|
| 做什么 | 允许网页调 JS-SDK（分享、扫码、上传图片等） | OAuth2.0 授权登录、拿 openid/用户信息 | 微信内访问该域名页面不被重排、不弹风险提示 |
| 本项目是否必需 | 需要（H5 分享/活动页） | 需要（公众号内做用户打通） | 需要（菜单挂 H5 时体验更好） |
| 数量上限 | 5 个 | 2 个（认证服务号） | 3 个 |
| 修改频率 | 每月最多 5 次 | 每月最多 5 次 | 每月最多 5 次 |
| 协议 | 仅 https，不支持 IP | 仅 https，不支持 IP | 仅 https，不支持 IP |
| 备案 | 必须 ICP 备案，新备案需满 24 小时 | 同左 | 同左 |
| 子域名 | 支持子域名 | 填主域名即覆盖其子域名 | 按填写的域名 |
| 校验方式 | 下载 `MP_verify_xxxx.txt` 放到域名根目录可访问 | 同左 | 同左（校验文件内容不同，不可混用） |

#### 3.3.2 本项目建议填写值

| 域名类型 | 填写 | 理由 |
|----------|------|------|
| JS 接口安全域名 | `m.lunails.cn`、`lunails.cn` | 客户 WebApp、官网活动页需要 JS-SDK |
| 网页授权域名 | `m.lunails.cn` | 授权回调收敛到一个域名，便于后端白名单校验 |
| 业务域名 | `m.lunails.cn`、`lunails.cn` | 菜单挂 H5、活动页免风险提示 |
| （不需要） | `api.lunails.cn` | 纯接口域名，不承载网页，不必配 |

> 若将来要做「公众号内打开 H5 支付」或更多 H5 场景，再把 `m.lunails.cn` 的授权回调路径统一到后端 `/api/wechat/official/oauth/callback`。

#### 3.3.3 校验文件放置方案（本项目具体做法）

三个域名都指向同一台 ECS 的 nginx，需要让 `https://<域名>/MP_verify_xxxx.txt` 可访问。

**方案 A：放在静态站点根目录（推荐，改动最小）**

- `m.lunails.cn` → 由 `client-web` 容器提供静态文件：把下载的 `MP_verify_xxxx.txt` 放到 `client-frontend/public/`，重新构建部署 `client-web` 即可访问。
- `lunails.cn`（官网）→ 同理放到官网静态资源目录，随官网部署。
- 注意：SPA 的 nginx 通常有 `try_files ... /index.html` 兜底，真实存在的静态文件会优先返回，无需额外配置；上传后**必须用浏览器实测**。

**方案 B：在边缘 nginx 直接返回（不改前端构建）**

在 `deploy/nginx/conf.d/` 对应域名 server 块加：

```nginx
location = /MP_verify_xxxx.txt {
    default_type text/plain;
    return 200 "校验文件内容";
}
```

改完执行 `docker compose restart nginx`。适用于临时验证，**不建议长期**（微信换域名会换文件名）。

**验收（每个域名都做）**：浏览器打开 `https://<域名>/MP_verify_xxxx.txt` 能看到文件内容，再回后台点「保存」，提示校验通过。

#### 3.3.4 常见失败原因

| 现象 | 原因 |
|------|------|
| 提示域名未备案 | 域名未备案或备案未满 24 小时 |
| 校验失败 | 文件放在子目录、文件名写错、https 访问不通、被 SPA 兜底成 index.html |
| 保存按钮灰 | 当月修改次数用尽（5 次），等下月 |
| 填不进去 | 填写带了 `https://` 或路径，只填域名本身 |

### 3.4 消息推送配置（**必须先完成第 8 章的后端接口**）

| 配置项 | 建议值 | 说明 |
|--------|--------|------|
| 服务器地址 URL | `https://api.lunails.cn/api/wechat/official/callback` | 必须以 http(s) 开头，443 端口 |
| Token | 32 位随机串（`openssl rand -hex 16` 生成） | 长度 3–32 字符，用于签名校验；**与后端配置严格一致** |
| EncodingAESKey | 43 字符（后台可随机生成） | 安全模式加解密用 |
| 消息加解密方式 | 先「明文模式」灰度 → 切「安全模式」 | 明文便于首次排查；稳定后切安全模式（需后端实现 AES） |
| 数据格式 | XML（本项目按 XML 实现） | 支持 XML/JSON，选 XML 生态最完整 |

**保存时的验证机制**（后端必须实现，否则保存必然失败）：

```
微信 GET 请求：/callback?signature=xxx&timestamp=xxx&nonce=xxx&echostr=xxx
后端：1) 将 token、timestamp、nonce 三个参数按字典序排序
      2) 拼接成一个字符串做 sha1 加密
      3) 与 signature 比对；一致则原样返回 echostr，否则返回空/错误
```

**切换/停用**：任何时候可在后台把消息推送改为「停用」，或在 URL 前去掉勾选，公众号即回到后台自动回复模式，不影响小程序。

### 5.4 「智能回复」怎么实现（后台没有原生 AI）

微信公众平台后台**只提供关键词自动回复**，没有官方 AI 智能回复开关。想要"智能"有三种路径：

| 方案 | 做法 | 成本 | 适用阶段 |
|------|------|------|----------|
| A. 关键词规则（原生） | 后台配置 30 条高频词 | 0 成本 | **第一阶段必做**，覆盖 70% 咨询 |
| B. 微信对话开放平台 | `chatbot.weixin.qq.com` 创建问答库/技能 → 绑定公众号 → 未命中关键词的转给机器人 | 免费，配置工作量中等 | 第二阶段，关键词升级为语义问答 |
| C. 后端接管 + LLM | 消息推送回调里，未命中规则的消息转给后端，调用大模型生成回复（可带业务数据，如"我的预约到哪一步了"） | 需开发，需注意回复延迟（5 秒约束与异步回复） | 第三阶段，最能形成差异化 |

**方案 C 的关键技术约束（务必注意）**
- 微信要求回调 **5 秒内响应**，否则重试 3 次。调用大模型很可能超时，正确做法是：**先立即返回空串/"success"，再通过「客服消息接口」异步回复**（客服消息在用户发消息后 48 小时内可主动发送，正好覆盖这个场景）。
- 需在回调里做**幂等**（按 `MsgId` 去重），否则重试会造成重复回复。
- 涉及价格、预约状态等**敏感数据必须查后端真实数据**，不能让模型自由发挥。

推荐落地节奏：先 A（本周就能上线）→ 观察 2 周后台「消息分析」，把 Top 10 未命中问题补进关键词 → 再评估 B/C。

### 5.5 客服能力配置

| 项 | 说明 |
|----|------|
| 入口 | 公众平台 →「内容与互动」→「客服」 |
| 客服人员 | 添加客服微信号（店主/客服），支持多客服轮流 |
| 48 小时窗口 | 用户主动发消息后 48 小时内，可以主动下发客服消息；超过 48 小时需用户再次触发 |
| 菜单入口 | 可让「联系客服」菜单直接进入会话（后台菜单类型支持「客服」时优先用它） |
| 消息不丢 | 后端接管消息推送后，**务必在数据库留档**（用户、消息、时间），避免客服交接丢上下文 |
| 常见组合 | 关键词回复承接 70% → 客服消息承接 25% → 电话兜底 5% |

## 7. 第六阶段：通知与复购（P1）

### 7.1 公众号能发什么消息（选型先看清）

| 能力 | 触发条件 | 本项目用途 | 推荐度 |
|------|----------|-----------|--------|
| 模板消息 | 认证服务号，用户已关注，需申请模板并通过类目审核 | 预约成功、状态变更、服务完成 | ⭐⭐⭐ |

| # | 模板用途 | 建议字段 | 对应业务事件 |

| 2 | 预约状态变更通知 | 订单号、变更后状态、时间 | 待确认/已确认/待上门 |
| 3 | 服务前提醒 | 服务项目、时间、地址、美甲师 | 复用小程序现有提醒（次日/1 小时） |
| 4 | 服务完成待评价 | 订单号、完成时间、评价入口 | 订单完成 |
| 5 | 设计需求回复通知 | 需求编号、回复内容 | 定制需求被回复 |

申请路径：开发者平台 → 服务号 → 开放能力 / 接口权限 → 模板消息 → 从模板库选用（不同行业类目可选的模板不同）。

### 7.3 通知链路（UnionID 是桥）

```
用户在小程序下单
   ↓ WechatIdentity(appId=小程序, openId=小程序openid, unionId)
按 unionId 找到 WechatIdentity(appId=公众号, openId=公众号openid)
   ↓ 用公众号 access_token 调模板消息/订阅通知接口
消息出现在用户的公众号会话或服务通知里
```

前置条件：**第 2.3 节的开放平台绑定必须完成**，否则拿不到 unionId，链路断掉。
补充条件：用户必须**已关注公众号**（模板消息）或**已订阅**（订阅通知）；未关注时只能用小程序订阅消息（现有能力，不受影响）。

### 7.4 带参数二维码（渠道推广）

- 服务号支持创建带参数二维码，用于区分来源（小红书、抖音、门店物料、美甲师个人海报）。
- 用户扫码关注 → 回调 `subscribe` 事件带 `EventKey`（如 `qrscene_channel_xiaohongshu`）→ 后端记录来源 → 后续可做分渠道统计与定向推送。
- 临时二维码有效期 30 天，永久二维码数量有限，按场景选择。

### 8.4 关键实现要点（8 条，每条都是踩坑点）

1. **raw body**：NestJS 默认解析 JSON，XML 会拿不到原文。需在 bootstrap 里为回调路径挂 `express.text({ type: ['text/xml', 'application/xml'] })`，否则签名校验必失败。
2. **签名算法**：`sha1([token, timestamp, nonce].sort().join(''))`，与 `signature` 严格比对（出错 99% 是排序或大小写问题）。
3. **安全模式解密**：`AES-256-CBC`，key = `base64decode(EncodingAESKey + '=')`，PKCS#7 去填充，先校验 `msg_signature = sha1(sorted(token, timestamp, nonce, encrypt))`。
4. **5 秒响应 + 幂等**：微信超时重试 3 次。按 `MsgId`/`FromUserName+CreateTime` 做去重（建议落库或内存 LRU）；不回复时立即返回 `success`，需要异步的（如 LLM、外部查询）走客服消息补发。
5. **access_token 中控**：有效期 7200 秒，提前 300 秒刷新；单实例部署（本项目后端为单容器）用进程内缓存 + 刷新锁即可，**不要每次请求都取**（有日调用上限，且新旧 token 有 5 分钟并存期）。
6. **错误码兜底**：`40001`（token 无效）→ 强制刷新重试一次；`40164`（IP 不在白名单）→ 检查 3.2；`45015`（客服消息超 48 小时）→ 降级为不发送并记日志；`40003`（openid 无效）→ 检查 unionId 映射。
7. **消息落库**：所有收到的消息/事件写一张 `OfficialMessageLog`（或复用现有日志表），用于客服交接、数据分析和排障。
8. **失败降级**：公众号任何环节失败**不得影响**订单主流程。所有公众号调用包在 try/catch 中，失败仅记录日志（与现有推送服务的容错方式保持一致）。

## 10. 常见问题与排障

| 现象 | 根因 | 处置 |
|------|------|------|
| 保存消息推送提示「配置失败」 | 后端未上线 / 签名不对 / URL 不可达 | 用浏览器 GET 回调 URL 带参数自测；检查 sha1 排序；确认 https 证书链完整 |
| 接口返回 `40164` | IP 不在白名单 | 3.2 添加 ECS IP，等 5 分钟 |
| 接口返回 `40001` | access_token 失效 | 强制刷新一次；检查是否多实例各自缓存 |
| 客服消息返回 `45015` | 超过 48 小时窗口 | 不再重试，等用户下次触发；或改用模板消息 |
| 菜单保存提示「小程序未关联」 | 未关联或关联未完成 | 回到 2.2 完成双端确认 |
| 菜单不更新 | 微信缓存（老用户 24 小时） | 取消关注再关注立即生效 |
| 菜单点击白屏 | 小程序页面未发布或路径写错 | 确认页面已上线，路径以 `/pages/...` 开头且拼写完全一致 |
| `redirect_uri` 参数错误 | 回调域名与网页授权域名不一致 | 回调必须落在已配置域名下，且用 https |
| H5 分享无自定义标题 | 未配 JS 接口安全域名或签名错 | 补配域名；检查 `jsapi_ticket` 缓存与签名参数（nonceStr/timestamp/url 去锚点） |
| 用户发消息无任何回复 | 消息推送已停用 / 后端 5 秒超时 | 查后端日志与消息推送状态；确保先返回 `success` 再异步处理 |
| 关注没收到欢迎语 | 关注事件未处理 / 后台回复被覆盖 | 消息推送开启时，**后台自动回复不再生效**，欢迎语需后端自己实现（或关掉消息推送用后台配置） |

> ⚠️ 重要机制：**消息推送（服务器配置）一旦启用并生效，公众号后台的「自动回复」将不再触发**，所有消息都会发到你的服务器。所以选择「后端接管」还是「后台自动回复」，必须二选一并与团队说明。

- `click` 类型的 `key` 由后端在消息回调里识别并回复对应内容（`MENU_CONTACT_SERVICE` → 返回客服引导；`MENU_ABOUT_US` → 返回品牌介绍）。

### E.4 重要机制提醒

- **消息推送一旦启用，公众号后台的「自动回复」将不再触发**，全部由本模块接管（欢迎语、关键词、兜底文案都在代码里）。如果你更希望用后台配置自动回复，那就**不要**启用消息推送，此时菜单、图文、客服仍可正常使用。
- 两种模式可以随时切换：后台停用消息推送 → 回到后台自动回复；重新启用 → 由后端接管。
- 所有微信接口调用失败都不会影响下单等主流程，仅记录日志。
