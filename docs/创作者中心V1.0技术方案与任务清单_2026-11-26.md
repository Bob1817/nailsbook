## 2. V1.0 新增/改造接口契约（API Spec）

### 2.1 微信小程序扫码登录（`backend/src/technician-auth`）

1. **`POST /api/technician/auth/qr/create`**（公开接口，限流）
   - **出参**：
     ```json
     {
       "sceneToken": "qr_xxx...",
       "qrCodeImageBase64": "data:image/png;base64,...",
       "expiresAt": "2026-11-26T15:50:00.000Z"
     }
     ```
   - **说明**：服务端生成临时 `sceneToken`（有效期 3 分钟，存 Redis 或内存/DB 临时表），调用微信服务端接口生成携带 `scene` 的小程序码或前端渲染扫码 URL。

2. **`GET /api/technician/auth/qr/status?sceneToken=...`**（公开接口，前端 2s 轮询）
   - **出参**：
     ```json
     {
       "status": "pending | scanned | confirmed | expired",
       "accessToken": "...",
       "refreshToken": "...",
       "technician": { "id": 1, "name": "...", "avatarUrl": "..." }
     }
     ```
   - **安全要求**：仅当 `status === 'confirmed'` 时返回一次 `accessToken` 与 `refreshToken`，读取后立即销毁该 `sceneToken`。

3. **`POST /api/technician/auth/qr/confirm`**（需小程序端美甲师 JWT 鉴权）
   - **入参**：`{ "sceneToken": "qr_xxx...", "action": "scan | confirm | cancel" }`
   - **出参**：`{ "success": true }`
   - **说明**：小程序扫码打开确认页时传 `scan`（Web 端显示“已扫码，请在手机确认”）；点击确认登录传 `confirm` 并绑定 `request.user.technicianId`。

### 2.2 作品批量操作与排序（`backend/src/technician-works`）

1. **`POST /api/technician/works/batch`**（需 `TechnicianJwtAuthGuard` + `TouristGuard`）
   - **入参**：
     ```json
     {
       "workIds": [101, 102, 103],
       "action": "show | hide | delete | add_tags | remove_tags | update_price",
       "tags": ["法式", "裸色"],
       "standardPrice": 268
     }
     ```
   - **校验与出参**：校验所有 `workIds` 归属 `request.user.technicianId`；返回 `{ "affected": 3 }`。

2. **`PUT /api/technician/works/reorder`**（需 `TechnicianJwtAuthGuard` + `TouristGuard`）
   - **入参**：`{ "orderedWorkIds": [105, 101, 102] }`
   - **说明**：按数组下标批量更新 `sortOrder`。

3. **`POST /api/technician/uploads/image` 限流调整**
   - 将 `@Throttle` 从 `30/60s` 调整为 `120/60s`（或新增多图并发队列支持），满足桌面端一次拖拽上传 20 张图片的需求。

| 路由 | 页面定位 | 处理方式 |

## 4. 研发任务拆解（按执行顺序）

### Phase 1：后端接口补齐与单测（`backend/`）
- **BE-1**：实现 `technician-auth` 扫码登录三接口（`qr/create`、`qr/status`、`qr/confirm`）及单元测试。
- **BE-2**：实现 `technician-works` 批量操作接口（`POST /works/batch`）与排序接口（`PUT /works/reorder`）及权限/归属单测。
- **BE-3**：放宽 `POST /technician/uploads/image` 限流阈值至 `120/60s`，支持桌面端批量上传。

### Phase 2：小程序扫码确认页联动（`client-wxapp/`）
- **WX-1**：在美甲师工作台增加「扫一扫登录电脑端」入口及扫码确认页（调用 `qr/confirm`）。

### Phase 3：前端桌面端框架与扫码登录（`technician-frontend/`）
- **FE-1**：重构 `MainLayout.tsx` 为桌面端「左侧固定导航 + 顶栏 + 主工作区」布局，收敛导航菜单。
- **FE-2**：重构 `Login.tsx`，默认展示扫码登录卡片与状态轮询，保留手机号密码登录切换。
- **FE-3**：对齐 `services/works.ts` 与 `services/insights.ts` 类型定义至后端最新 DTO。

### Phase 4：创作首页与作品工坊核心功能（`technician-frontend/`）
- **FE-4**：重构首页概览（核心数据卡片 + 近 30 天趋势图 + 分享转化漏斗 + 拖拽直达发布器）。
- **FE-5**：重构 `WorksPage.tsx`（网格/表格双视图、多维筛选、草稿箱 Tab、批量操作工具栏、拖拽排序）。
- **FE-6**：新建桌面端双栏作品发布/编辑页（并发队列上传进度条、前端压缩、封面/图片排序、基础服务与阶梯定价选择、标签模板点选、一键复用上条参数、右侧小程序预览）。

### Phase 5：联调、门禁检查与部署准备
- **QA-1**：运行 `technician-frontend` 中性色门禁检查（`npm run check:colors`）与 `npm run build` 构建验证。
- **QA-2**：运行 `backend` 相关模块单测（`technician-auth`、`technician-works`、`technician-insights`）。
- **OPS-1**：确认 Nginx/域名路由（如 `creator.xxx.com` → `tech-web:80`），通过 CI 构建镜像并更新 ECS。
