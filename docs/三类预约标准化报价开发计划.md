# 三类预约标准化报价开发计划

## 目标与边界

- 微信小程序支持作品同款、基础服务、个性化定制三类预约。
- 基础服务是价格和时长的唯一组成单位，作品与预约保存不可变快照。
- 首期合规模式继续强制仅到店，不提供上门服务、上门费或待上门入口。
- 微信支付保持关闭，本期价格只用于报价确认和经营记录。

## 业务状态

| 类型 | 提交价格 | 提交后状态 | 后续状态 |
| --- | --- | --- | --- |
| 作品同款 | 作品服务合计、作品标准报价 | `pending_confirm` | 美甲师确认后 `pending_shop` |
| 基础服务 | 客户所选服务合计 | `pending_confirm` | 美甲师确认后 `pending_shop` |
| 个性化定制 | 待报价 | `pending_quote` | 美甲师组合报价 → `pending_agree` → 客户确认后 `pending_shop` |

## 数据规则

1. 金额快照使用“分”的整数存储。
2. 作品服务明细保存服务 ID、名称、单价、时长、数量和小计快照。
3. 预约服务明细保存相同快照，并标记来源：`work`、`client`、`quote`。
4. `服务合计 - 优惠金额 = 最终价格`，优惠不能小于 0 或超过服务合计。
5. 总时长为所有服务行的 `时长 × 数量` 之和。
6. 历史作品和预约不能因基础服务后续改价而变化。

## 开发任务

### T1 数据模型与迁移

- `NailWork` 增加服务合计、标准报价和总时长。
- 新增 `NailWorkServiceLine` 作品服务快照表。
- `Order` 增加预约类型、服务合计、优惠、最终报价和总时长。
- 新增 `OrderServiceLine` 预约服务快照表。
- 提供 SQLite 可部署迁移和旧数据兼容逻辑。

验收：Prisma 校验、迁移 SQL 在空库和现有 SQLite 副本上均能执行。

### T2 后端定价与预约创建

- 客户预约统一从 `Service` 表读取有效服务，不再以 `serviceItems` JSON 为主数据源。
- 作品同款从作品快照生成预约快照和标准报价。
- 基础服务按所选服务生成预约快照。
- 个性化定制创建待报价预约，不生成虚假价格。
- 后端重新计算价格和时长，拒绝客户端篡改。

验收：三类创建接口单元测试、失效服务/跨美甲师服务/篡改价格测试。

### T3 组合报价与状态机

- 美甲师只能选择自己的有效基础服务组成报价。
- 支持服务数量、优惠金额和优惠说明。
- 报价保存预约服务快照，并计算最终价格与总时长。
- 定制预约由客户确认报价后直接进入 `pending_shop`。
- 标准预约由美甲师确认后进入 `pending_shop`。

验收：合法与非法状态转换、优惠边界、重复确认和幂等测试。

### T4 排期规则

- 可预约时间只校验预约开始时刻。
- 结束时间按服务总时长计算，可跨越休息时段或营业区间末尾。
- 完整占位区间仍参与其他预约和人工锁定时段的冲突校验。
- 报价导致时长变化时重新校验并更新占位。

验收：跨休息时间允许、开始时间越界拒绝、跨区间冲突拒绝测试。

### T5 美甲师小程序

- 作品新增/编辑必须选择基础服务并填写作品标准报价。
- 展示服务合计、作品报价、优惠差额和总时长。
- 定制预约报价页改为服务组合选择，不再允许只输入总价。

验收：作品发布校验、组合报价、折扣和失败恢复真机流程。

### T6 客户小程序

- 明确三个入口：预约同款、选择服务、个性化定制。
- 作品预约展示服务组成、服务合计、作品标准报价和时长。
- 基础服务预约展示逐项价格、合计和时长。
- 定制预约提交时显示待报价；收到报价后展示服务组成和优惠。

验收：三类预约从发起到待到店的完整真机流程。

### T7 回归与发布验收

- Prisma、后端单元/契约测试、小程序静态检查和发布门禁全部通过。
- 验证首期仅到店、支付关闭、唯一美甲师限制没有被绕过。
- 输出生产迁移、备份、部署和回滚步骤。

## 2026-08-21 实施与验收结果

- T1–T6 已实施：数据快照、三类预约、组合报价、开始时间规则、作品定价、客户价格明细均已落地。
- Prisma `validate` 和后端 TypeScript 构建通过。
- SQLite 迁移已在现有 `dev.db` 的临时副本执行，外键检查通过，两张快照表可正常读取。
- 后端全量自动化：78 个测试套件、323 个测试、1 个快照全部通过。
- 小程序发布门禁：全量静态检查、导航、完成服务到发布作品、转化归因、首期合规检查全部通过。
- 合规边界保持：小程序首期仍强制仅到店，未开启微信支付、上门服务或多商户能力。

上线前仍需在微信开发者工具执行三类预约的真机点击验收，这是发布操作的人工门禁，不影响本次代码自动化验收结论。
