# NailBook 微信小程序首期合规上线开发计划 v2

**版本：** v2.0  
**日期：** 2026-08-20  
**状态：** 待确认后执行  
**适用范围：** `client-wxapp`、为小程序提供服务所必需的 `backend` 代码与生产配置  
**明确排除：** `client-frontend`、`technician-frontend`、`admin-frontend`、`landing-frontend`、iOS、Flutter、官网及其他端

## 1. 目标与边界

### 1.1 上线目标

在短期无法取得 ICP 经营许可证和 EDI 许可证的条件下，将首期产品收敛为：

> 由科技公司运营、仅服务一家指定美甲店的经营管理工具。美甲店是唯一线下美甲服务提供者；小程序提供作品展示、客户绑定、到店预约、报价确认、沟通、客户管理和服务提醒，不向第三方商户开放交易平台能力。

本计划的目标是让线上实际功能、协议、备案、微信后台申报和审核演示保持一致，降低被认定为经营性信息服务或第三方在线交易处理平台的风险。

### 1.2 重要说明

- 本计划不是通过隐藏文案规避监管，而是实际停止对应业务和技术能力。
- 是否需要 ICP/EDI 最终取决于真实业务模式和主管部门认定，代码改造不能替代法律结论。
- 首期不得开放第三方美甲师自主入驻、第三方门店交易、平台抽佣、线上代收款或现金等价奖励。
- 如果后续开放多商户经营、在线支付、平台收费、交易撮合或基金抵扣，必须重新进行许可证评估，不能直接打开功能开关上线。

## 2. 首期允许与禁止的能力

| 领域 | 首期允许 | 首期禁止/关闭 |
|---|---|---|
| 服务主体 | 唯一指定美甲店 | 第三方美甲师/门店自主入驻 |
| 服务方式 | 到店服务 | 上门服务、位置选点、服务半径 |
| 作品传播 | 本店作品、店铺主页、微信好友/朋友圈分享 | 全平台公共流量分发、竞价排名 |
| 客户关系 | 邀请绑定、来源归因、单店客户档案 | 平台向多商户分配客户 |
| 预约 | 选择项目/时间、报价、确认、改期、取消、完成 | 平台撮合、多商户比价 |
| 沟通 | 已绑定或有预约关系的客户与美甲师沟通 | 陌生人社交、群聊、开放私信 |
| 付款 | 线下付款说明、内部记录线下已收款 | 微信支付、定金/尾款在线支付、平台代收 |
| 推荐 | 分享来源、推荐关系记录 | 美甲基金、现金余额、百分比返利、抵扣 |
| 软件收费 | 首期指定账号免费使用 | 套餐价格、在线订阅、升级付费 |
| 提醒 | 微信订阅消息、小程序内消息 | 以 FCM 作为小程序离线通知 |
| 图片工具 | 本地拼图、滤镜、分享图 | 无真实能力支撑的“AI 生成”宣传 |

## 3. 发布门禁

以下条件任一未满足，不得上传审核版：

1. 小程序静态检查、发布门禁、后端构建和相关测试全部通过。
2. 新请求无法创建上门订单，后端不能只依赖前端隐藏。
3. 生产环境微信支付能力强制为关闭，客户端无支付入口，服务端拒绝支付创建。
4. 生产环境无美甲基金、返利、抵扣、订阅套餐和第三方入驻入口。
5. 小程序完成独立备案；主体、名称、协议、隐私政策和微信后台资料一致。
6. 手机号、图片等隐私接口在明确同意后调用，微信隐私保护指引与实际处理一致。
7. 预约前提醒通过微信订阅消息真机送达，而不是只写入站内消息。
8. 审核账号只能看到唯一指定美甲店，不出现测试美甲师、上门服务或平台型演示数据。
9. iOS 和 Android 微信正式版均完成核心流程真机验收。

## 4. 开发阶段

### Phase 0：修复基线并冻结上线范围

**目标：** 先恢复可验证基线，避免在损坏版本上继续开发。

| ID | 任务 | 主要范围 | 验收 |
|---|---|---|---|
| P0-01 | 修复预约页语法错误 | `client-wxapp/pages/client/create-order/index.js` | `node --check`、小程序静态检查通过 |
| P0-02 | 建立首期功能开关 | 后端集中配置：单店、到店、无支付、无基金、无订阅 | 生产默认值为合规关闭状态，缺失配置时 fail-closed |
| P0-03 | 固定唯一门店和唯一可运营美甲师范围 | 后端公开查询、绑定、预约接口 | 非白名单美甲师不出现在公开接口且不能接单 |
| P0-04 | 更新产品基线文档 | 本计划及审核清单 | 不再把旧 v1“仅隐藏 UI”计划作为发布依据 |

**预计：** 0.5–1 个开发日。

### Phase 1：关闭可能改变许可判断的业务能力

**目标：** 从页面、路由、接口、状态机和数据生成五个层面同时关闭。

#### 1A. 上门服务关闭

- 小程序只显示固定门店和到店服务。
- 移除地址管理、位置权限、上门设置、服务半径和路程展示。
- 创建预约请求不再传递客户地址或上门类型。
- 后端 DTO/服务层拒绝新建或变更为上门服务。
- 定时任务和状态机不再为新订单生成 `pending_home`。
- 历史数据只保留兼容读取，不删除、不作为新业务入口。
- 生产演示数据和审核账号中不得出现“上门”。

#### 1B. 在线支付关闭

- `wechatPay` 生产能力固定返回不可用。
- 小程序不注册交易订单入口，不显示定金、尾款、退款、支付结果页面。
- 后端支付创建接口在首期模式下直接拒绝，不得仅隐藏按钮。
- 报价确认后展示“付款由客户与门店线下完成”。
- 如保留内部收款记录，字段和文案明确为“线下收款记录”，不生成在线支付成功流水。

#### 1C. 推荐基金关闭

- 从 `app.json` 和所有菜单/分享入口移除推荐基金、邀请基金页面。
- 保留分享来源、直接推荐人和绑定来源记录。
- 关闭奖励资格计算、基金发放、基金抵扣和冲正任务。
- 后端基金余额及抵扣写接口在首期模式下拒绝。
- 页面不得出现人民币奖励、余额、待生效、抵扣、5% 等信息。

#### 1D. 软件订阅关闭

- 从 `app.json` 和美甲师菜单移除订阅页面。
- 首期唯一美甲师账号直接赋予所需功能，不展示套餐、额度、升级和客服售卖入口。
- 后端禁止创建订阅支付意向；现有权益判断使用首期固定授权。

#### 1E. 平台化入口关闭

- 游客和客户只看到唯一门店及其作品。
- 关闭跨门店发现、多美甲师比较、公共咨询线索和自主入驻入口。
- 美甲师注册继续由后台既有受控方式创建，但生产环境不对外提供入驻入口。
- 公开作品分享必须绑定唯一门店/美甲师来源，不得落入全平台流量池。

**预计：** 3–4 个开发日。

### Phase 2：主体、协议与隐私合规

**目标：** 让代码行为、用户告知和微信后台申报完全一致。

| ID | 任务 | 验收标准 |
|---|---|---|
| P2-01 | 重写用户协议 | 明确科技公司为运营方、指定美甲店为线下服务方；删除撮合、上门、在线支付等表述 |
| P2-02 | 重写隐私政策 | 列明手机号、OpenID、预约、聊天、照片、客户档案的目的、范围、保存期限和权利渠道 |
| P2-03 | 显式协议同意 | 不再使用“登录即同意”；未勾选时不得手机号授权、注册或登录 |
| P2-04 | 微信隐私接口适配 | 接入微信隐私授权流程，后台隐私保护指引与代码扫描一致 |
| P2-05 | 注销与数据权利入口 | 用户可提交注销、查询、更正、删除请求；后台有可审计处理路径 |
| P2-06 | 备案信息展示 | 小程序显著位置展示小程序备案编号和运营主体信息 |

**预计：** 1.5–2 个开发日。协议最终文本建议由熟悉互联网业务的律师复核。

### Phase 3：微信小程序提醒闭环

**目标：** 满足预约安排和客户提醒的核心诉求。

| ID | 任务 | 验收标准 |
|---|---|---|
| P3-01 | 申请订阅消息模板 | 使用与实际业务一致的预约确认、预约提醒、改期/取消模板 |
| P3-02 | 客户授权入口 | 预约提交/确认后由用户主动触发 `requestSubscribeMessage` |
| P3-03 | 美甲师授权入口 | 接单或设置提醒时由美甲师主动授权 |
| P3-04 | 保存授权及发送结果 | 记录模板、角色、业务对象、发送状态、微信错误码和时间 |
| P3-05 | 后端微信发送服务 | 预约前一天、前一小时及改期/取消按规则发送，幂等且可有限重试 |
| P3-06 | 渠道语义修正 | 微信订阅消息、站内消息、WebSocket 分开记录；FCM 不再被视为小程序送达 |

**预计：** 2–3 个开发日，另需等待微信模板申请和真实账号配置。

### Phase 4：小程序信息架构和包体收缩

**目标：** 减少审核暴露面和回归范围，不开发其他端。

- 将当前约 70 个主包页面收缩到首期必要页面。
- 主包保留登录、首页、作品、预约、消息、我的。
- 客户和美甲师次级功能按微信小程序分包组织。
- 不注册上门地址、支付、交易订单、基金、订阅、平台营销活动页面。
- 将 `ai-photo` 改名为“朋友圈美照”或“分享图制作”；仅做本地排版和滤镜。
- “发现”改为“作品”或“灵感”，内容只来自唯一指定美甲店。
- 所有交互控件保持至少 44px，验证安全区、键盘遮挡和弱网状态。

**预计：** 1.5–2 个开发日。

**预计：** 2–3 个测试日。

## 5. 非代码上线任务

这些任务不能由代码替代，必须与开发并行：

1. 以科技公司主体完成微信小程序认证和小程序备案。
2. 在微信后台按实际功能选择服务类目；提交前截图留档。
3. 准备科技公司营业执照、指定美甲店个体工商户营业执照及双方合作/授权说明。
4. 配置服务器域名、上传域名、WebSocket 域名，全部使用已备案域名和 HTTPS/WSS。
5. 在微信后台填写隐私保护指引，逐项对应实际使用的隐私接口。
6. 申请订阅消息模板并配置生产模板 ID。
7. 准备审核账号、审核路径和说明，明确“单店、到店、线下付款、不开放入驻”。
8. 提交前由法律顾问或所在地通信管理部门咨询渠道复核真实业务是否仍需经营许可。

| 阶段 | 预计工期 | 依赖 |
|---|---:|---|
| Phase 0 基线与开关 | 0.5–1 日 | 无 |
| Phase 1 业务能力关闭 | 3–4 日 | Phase 0 |
| Phase 2 协议与隐私 | 1.5–2 日 | 主体信息确认 |
| Phase 3 微信提醒 | 2–3 日 | 微信配置、模板申请 |

若以最快上线为目标，可先完成 Phase 0、1、2、必要的 Phase 4 和核心回归，在订阅消息模板审核期间并行开发 Phase 3；但订阅消息未真机送达前，不能宣称“预约实时提醒”已经完成。

## 7. 最终完成定义

只有同时满足以下条件，首期才视为可提交审核：

- 代码门禁全部通过，无已知 P0/P1 缺陷。
- 小程序备案已完成，备案编号已展示。
- 微信后台类目、隐私指引和实际功能一致。
- 线上只能访问唯一指定美甲店和到店服务。
- 前后端均无法发起上门、在线支付、基金奖励/抵扣、套餐付费和第三方入驻。
- 客户与美甲师核心业务闭环在两类真机上通过。
- 微信订阅消息在小程序退出后仍可到达。
- 审核材料和审核账号没有测试数据、平台化文案或被关闭功能。
