# 首页 Hero 推荐与客户绑定改造

## 已实现规则

- 每位美甲师最多设置 3 个客户首页推荐作品，支持排序、取消及明确选择旧作品后替换。与个人主页精选（最多 6 个）独立。
- 仅本人公开、审核通过、未归档且有封面的作品可推荐；作品失去展示资格时自动释放推荐位。
- 客户最多占用 5 个绑定名额，已绑定和待审核申请共同计数。数据库约束覆盖并发新增；待审核转正式绑定不重复占用。
- 客户“我的”页仅展示前 2 位，显示绑定数量和待审核数量，完整操作集中到“我的美甲师”管理页。
- 登录客户首页最多展示 5 个作品，按默认美甲师优先、绑定时间倒序确定美甲师顺序，各取一个后进入下一轮，单人最多贡献 3 个。无作品的美甲师跳过。
- 单作品不自动轮播；未绑定、暂无推荐、加载失败分别展示对应状态。
- 小程序及客户、美甲师 Web 端均已接入。

## 数据与一致性

迁移：`backend/prisma/migrations/20260908100000_hero_and_binding_limits/migration.sql`。

新增独立 heroSlot，按原精选排序迁移每位美甲师前 3 个符合资格的作品。保留原精选和全部历史绑定；历史超过 5 个的客户不自动解绑，名额降至上限以下才能新增。历史超量绑定的 Hero 仅选择排序靠前的 5 位有推荐作品的美甲师参与轮询。

推荐列表保存携带 expectedWorkIds，通过事务与旧列表校验避免并发覆盖；失败回滚，前端重新获取服务端状态。数据库唯一约束及触发器兜底数量、资格和绑定容量。

## 上线顺序

当前完成代码改造，尚未部署线上。先按项目发布流程备份数据库，在后端执行 `npx prisma migrate deploy`、`npx prisma generate` 并构建发布后端，再发布 Web 和小程序。不能用 `prisma db push` 替代迁移，因为数量和资格约束包含 SQL 触发器。

线上后端尚未提供新的推荐管理接口；后端升级前，小程序新管理页面会展示加载失败，不能视为线上已生效。
