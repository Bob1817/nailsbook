# 预约流程优化设计文档

**日期：** 2026-06-01  
**作者：** Claude + shibo  
**状态：** 已确认，待实现

---

## 背景与问题

当前预约流程存在以下痛点：

1. **预约入口割裂**：用户与美甲师沟通完成后，需要退出对话进入独立预约页操作，上下文断裂
2. **表单过于繁琐**：需要从预设服务列表中选择，且自定义服务要求填写标题（必填），与实际沟通场景脱节
3. **口头预约无数字化路径**：美甲师通过微信口头完成的预约，无法便捷地转化为系统内预约记录

---

## 核心场景

1. 用户打开客户端，与美甲师沟通后，在对话中直接发起预约
2. 用户看到美甲款式，沟通确认后，在对话中直接预约
3. 用户仅在微信沟通，美甲师代为创建预约并发送确认链接，用户无需登录 App 即可确认

---

## 方案选择：外科手术式扩展

**保留现有独立预约页（`ClientCreateOrderScreen`）完整功能不变**，在聊天场景叠加新能力。三个独立能力模块：

```
能力 A：聊天内一键发起预约（客户端 & 美甲师端）
  └─ ChatBookingSheet（新组件）

能力 B：简化预约表单（仅在 ChatBookingSheet 内生效）

能力 C：美甲师生成微信确认链接
  └─ 美甲师填写 → 后端生成 token → H5 无登录确认页
```

---

## 能力 A & B：ChatBookingSheet 组件

### 触发方式

两端 `ChatScreen` Header 右侧新增「📅 发起预约」胶囊按钮，点击后底部面板从下滑出，聊天内容保持可见于面板上方。

### 上下文传递

- **客户端**：`ChatScreen` 已有 `conversationId`，通过会话查询关联的 `technicianId`，Sheet 直接使用，无需用户重新选择美甲师
- **美甲师端**：通过 `conversationId` 获取关联的 `customerId`

### 表单字段（客户端发起）

| 字段 | 必填 | 逻辑 |
|------|------|------|
| 服务方式 | 是 | 美甲师仅支持一种时自动选中不展示；两种都支持时展示「上门/到店」二选一 |
| 地址 | 条件必填 | 仅上门美甲时显示；见地址逻辑 |
| 预约日期 | 是 | 默认明天，点击唤起日期选择器 |
| 预约时间 | 是 | 横向时间槽选择，复用现有时间槽列表 |
| 服务说明 | 否 | 多行文本框，placeholder：「简短描述需求，或上传参考图…」 |
| 参考图片 | 否 | 最多 3 张，复用现有图片上传逻辑 |

### 表单字段（美甲师端发起——帮客户创建）

在客户端字段基础上，额外新增：

| 字段 | 必填 | 说明 |
|------|------|------|
| 服务价格 | 条件必填 | 数字输入框，单位：元；仅美甲师端显示；勾选「转发微信确认」时必填，否则选填 |

### 地址逻辑（上门美甲）

```
有 1 个已保存地址 → 直接展示该地址，可点击切换
有多个已保存地址 → 下拉选择，底部提供「+ 新增地址」入口
无已保存地址     → 内联展示地址填写表单（姓名、电话、详细地址）
任何情况下       → 新增地址同步写入用户地址管理（POST /addresses）
```

### 提交行为

- **客户端发起**：`POST /orders`（现有接口），提交后跳转订单列表，Sheet 关闭
- **美甲师端发起**：`POST /orders/technician`（现有接口）；若勾选「转发微信」则额外传 `shareToClient: true`，返回 `confirmUrl` 并展示「复制链接」操作

## 能力 C：美甲师转发微信确认流程

### 完整时序

```
美甲师端                        后端                         用户（微信）
────────────────────────────────────────────────────────────────────────
1. 聊天中点「发起预约」
   填写预约信息 + 价格
   勾选「转发微信确认」
   点「生成确认链接」

                    2. POST /orders/technician
                       { ..., price, shareToClient: true }
                       → 创建 order
                       → status = pending_client_confirm
                       → 生成 confirmToken（UUID）
                       → tokenExpiresAt = now + 24h
                       ← 返回 { confirmUrl }

3. 系统展示 confirmUrl
   美甲师复制，粘贴到微信
   发给客户

                                              4. 客户点开微信链接
                                                 /confirm/{token}
                                                 （H5，无需登录）

                    5. GET /orders/confirm/{token}
                       → 验证 token 未过期、未使用
                       ← 返回预约详情（只读）

                                              6. 客户看到确认页：
                                                 ¥ 价格（核心展示）
                                                 时间、服务方式、地址

                                                 点击「确认预约」

                    7. POST /orders/confirm/{token}
                       → status = pending
                       → token 标记为已使用（不可重复确认）
                       ← 返回成功

                                              8. 显示静态成功页
                                                 「预约已确认」
                                                 无需跳转 App
```

### H5 确认页（`/confirm/:token`）

- Flutter 路由新增，不需要 `AuthSession`
- 页面只读，展示字段按优先级：
  1. **服务价格**（最显眼，核心确认项）
  2. 预约时间
  3. 服务方式
  4. 服务地址
- 操作：「取消预约」（软取消，status 恢复为 cancelled）和「确认预约」

### Token 安全规则

- Token 为 UUID v4，单次有效
- 有效期 24 小时，过期后显示「链接已失效，请联系美甲师重新发送」
- 确认后 token 标记 `usedAt`，再次访问显示「已确认」状态页

## 后端变更（最小化）

### Order 表新增字段

```
confirmToken          String?   // UUID，仅 shareToClient 时生成
confirmTokenExpiresAt DateTime? // = createdAt + 24h
confirmTokenUsedAt    DateTime? // 确认时写入，用于幂等判断
price                 Decimal?  // 美甲师填写的报价，新增字段；shareToClient=true 时必填
```

### Order status 新增枚举值

```
pending_client_confirm  // 等待客户通过链接确认
```

### 新增无鉴权路由

```
GET  /orders/confirm/:token   // 查询预约详情（无需 JWT）
POST /orders/confirm/:token   // 客户确认预约（无需 JWT）
```

## 不变的部分

- `ClientCreateOrderScreen`：独立预约页，保留完整的预设服务选择、自定义服务（含标题）等现有功能
- 现有订单状态机其余状态和转换逻辑
- 现有 `POST /orders` 和 `POST /orders/technician` 接口签名（仅追加字段，向后兼容）
- 美甲师端订单管理页面

---

## 成功标准

1. 客户在聊天界面点击「发起预约」，底部面板滑出，填写完成后订单出现在订单列表
2. 美甲师在聊天界面发起预约并生成链接，客户通过微信链接无需登录即可看到价格/时间/地址并确认
3. 现有独立预约页（`/client/orders/create`）功能不受影响
4. 新增的地址通过 Sheet 内入口保存后，在用户地址管理页也能看到
