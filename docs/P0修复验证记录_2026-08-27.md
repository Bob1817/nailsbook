## P0-02 代理与限流

| 层级 | 策略 |
| --- | --- |
| 边缘 Nginx | 用 remote_addr 覆盖 X-Forwarded-For，不接受客户端追加的伪造链 |
| Express | 仅信任 loopback/linklocal/私有地址；后端宿主机端口仅绑定 127.0.0.1 |
| 普通 HTTP | 每个路由、每个可信 IP，固定窗口 300 次/60 秒 |
| 认证 | 保留每个敏感路由 3–10 次/60 秒的覆盖策略 |
| 短信业务 | 每手机号/用途 3 次/分钟；跨 IP 请求仍受此业务限制 |
| 上传 | 每个上传路由/IP 30 次/分钟 |
| Socket.IO 新握手 | Nginx 每 IP 10 次/分钟，burst 10；已建立 sid 的 polling 不重复计数 |

首次真实 10 分钟压测失败：A 1800 次成功、2086 次 429；低频 B 967 次成功、224 次误限流。根因是已安装限流存储实现解封某 key 时清除了整个同名策略的过期定时器。改用独立 key 固定窗口存储，并用虚拟时钟重放 600 秒验证隔离。没有通过降低 B 频率或移除断言规避失败。

最终 10 分钟复测结果在本文件末尾归档。测试 A 每 150ms、B 每 500ms 请求同一路由，两者来自不同容器 IP；持续改变伪造 XFF。要求 A 必须出现 429、B 必须零 429、两者无其他请求错误。

复现命令：`bash deploy/qa-p0/run.sh`。输出保存在 `deploy/qa-p0/artifacts/`（已忽略版本控制），CI 自动上传。脚本创建并清理独立容器和临时数据库。生产 Nginx 配置使用临时证书执行 `nginx -t`，通过。

429 使用统一 Nest 错误结构、Retry-After 和中文等待提示；小程序测试确认不会自动刷新令牌、退出登录或无限重试。

边界：这是单实例 Nginx → NestJS 的 HTTP 隔离验证，不是生产 TLS、真实用户容量、WebSocket 长连接或支付实网压测。可信私网需继续由部署网络隔离保障；若增加 CDN/多级代理或后端多副本，必须重新配置可信链及共享限流存储。
