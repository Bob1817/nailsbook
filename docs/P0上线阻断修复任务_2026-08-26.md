## P0-01 修复超管后台服务端权限守卫失效

**目标**：后台 API 不仅验证管理员身份，还必须按 `@Permissions(...)` 执行服务端授权。

**复核纠正**：`JwtAuthGuard` 原本已在认证后执行 `@Permissions`，不能因独立 `PermissionGuard` 未注册就判定全部权限失效。实际缺口为邀请密钥及方法级艺术家申请路由缺少权限声明、JWT 权限撤销不即时生效，以及部分写操作审计未接入。

**主要代码范围**：

- `backend/src/app.module.ts`
- `backend/src/auth/auth.module.ts`
- `backend/src/auth/permission.guard.ts`
- `backend/src/auth/jwt.strategy.ts`
- 所有使用 `@Permissions(...)` 的后台控制器
- 后端合同测试与 e2e 测试

### 子任务

- [x] P0-01-A：复用已有 JwtAuthGuard 的认证后授权顺序，不重复注册守卫；通过运行时枚举检查类级和方法级后台路由。
- [x] P0-01-B：盘点全部后台路由，生成“HTTP 方法 + 路径 → 权限码”清单，检查 65 个权限声明是否完整、是否使用正确的权限码。
- [x] P0-01-C：确认无 `@Permissions` 的后台路由处理策略。明确为“仅登录可用”或“默认拒绝”，禁止无意间放行写接口。
- [x] P0-01-D：补充越权合同测试，至少覆盖超级管理员、只读管理员、无目标权限管理员、禁用管理员、无令牌五类身份。
- [x] P0-01-E：重点覆盖敏感接口：角色/权限管理、美甲师状态修改、客户和美甲师密码重置/查看、邀请密钥、微信登录与支付配置、报表导出。
- [x] P0-01-F：验证权限变更后的已签发 JWT 行为。如果权限仍嵌入 JWT，明确失效机制并补充测试，避免撤权后旧令牌继续生效。
- [x] P0-01-G：确认所有敏感写操作均产生不可缺失的操作日志，且拒绝请求不会泄露资源是否存在。

### 验收标准

- [x] 无权限管理员访问受保护接口统一返回 403；未登录返回 401；有权限管理员正常成功。
- [x] 低权限管理员无法查看或重置任何客户/美甲师密码，无法修改微信密钥或支付配置。
- [x] 自动扫描或测试证明每个 `/api/admin/**` 写接口都有明确权限策略。
- [x] 后端新增的权限测试通过，原有 329 项测试无回归。
- [x] CI 中权限合同测试为必过门禁。

## P0-02 修复 Nginx 反向代理下的全站共享限流

**目标**：限流按真实客户端或明确的业务主体生效，不得让不同用户共享 Nginx 容器 IP 的同一路由配额（原默认 60 次/分钟，不是全站所有路由合计）。

**风险**：NestJS 全局启用限流，但应用未配置可信代理。生产请求经 Nginx 转发后可能全部使用同一个代理 IP 计数，少量正常用户即可让全站进入 429。

**主要代码范围**：

- `backend/src/main.ts`
- `backend/src/app.module.ts`
- `deploy/nginx/conf.d/nailbook.conf`
- 限流配置、测试和部署文档

### 子任务

- [x] P0-02-A：在 Nest/Express 中只信任实际的 Nginx 代理层，正确解析 `X-Forwarded-For`；禁止无边界地信任任意客户端伪造的转发头。
- [x] P0-02-B：定义分层限流策略：登录、短信验证码、微信认证、上传、公开读接口、已登录业务接口、WebSocket 握手分别设置合理阈值。
- [x] P0-02-C：确认限流 key 的选择。匿名敏感接口按可信客户端 IP；已登录高频业务可按用户 ID/IP 组合；短信接口还需按手机号设置业务限流。
- [x] P0-02-D：为 429 响应提供统一错误结构和合理的重试提示，验证客户端不会无限重试形成请求风暴。
- [x] P0-02-E：在 Docker Compose 的 Nginx → backend 拓扑增加集成测试，模拟至少两个客户端 IP。
- [x] P0-02-F：执行短时并发测试，观察 429、CPU、内存和正常请求成功率；记录测试命令与结果。

### 验收标准

- [x] 客户端 A 达到自身限额后收到 429，客户端 B 同时仍可正常访问。
- [x] 伪造 `X-Forwarded-For` 不能绕过限流。
- [x] 登录/验证码爆破受到更严格限制，正常首页、订单和消息请求不会轻易触发限流。
- [x] 在生产等价拓扑下完成至少 10 分钟压力验证，无全站连锁 429。
- [x] 限流集成测试进入 CI 或部署前强制检查。
