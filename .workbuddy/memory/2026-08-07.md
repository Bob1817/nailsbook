# 2026-08-07 CPU 高负载优化

## 根因分析
部署后服务器 CPU 持续 98%+，经代码审查定位到 3 个核心问题。

## 修复内容

### 1. orders.scheduler.ts — 头号 CPU 杀手
- **重复调用**：`handleOrderStatusTransitions()`（每 5 分钟）调用了 `sendDayBeforeReminders`，而该方法有独立 `@Cron('0 20 * * *')`。导致每天执行 289 次而非预期的 1 次。
- **修复**：移除 `handleOrderStatusTransitions` 中对 `sendDayBeforeReminders` 的调用
- **无分页 findMany**：5 个 findMany 均无 `take` 限制，全表扫描 + 顺序 for...of 嵌套事务处理
- **修复**：全部 5 个 findMany 加上 `take: 100` + `orderBy: { id: 'asc' }`

### 2. typing.service.ts — 定时器泄漏
- 5s 硬超时 `setTimeout` 从未被清除，用户多次发送 typing:start 后定时器累积，每次触发 WebSocket 广播
- **修复**：将 debounce 和 hardTimeout 两个定时器引用都存储，`stopTyping` 时全部清除；`startTyping` 时先清除旧定时器再创建新的

### 3. avatar-url.interceptor.ts — 响应遍历优化
- 全局拦截器递归遍历每个 API 响应，即使无 avatarUrl 也创建新对象（深拷贝）
- **修复**：用 `changed` 标记只在确实转换了 avatarUrl 时才返回新对象，否则返回原引用（零分配）

### 4. ThrottlerGuard 内存 Map 膨胀
- NestJS 默认限流器用内存 Map，高 QPS 下 TTL 过期记录不释放
- **修复**：新建 `throttler-cleanup.service.ts`，每 5 分钟 Cron 清理过期记录
- 注入 `@Optional()` 避免测试环境崩溃

# 2026-08-07 客户端首页无效 token 导致 401 — 双端修复

## 根因
微信新用户 incomplete 注册后 token 存了 Storage，但 onLaunch 未校验直接 reLaunch 到首页。ClientHomeController 类级 ClientJwtAuthGuard 导致所有请求需有效 JWT → 401。

## 后端修复
- **ClientHomeController**：移除类级 `@UseGuards(ClientJwtAuthGuard)`，改为按路由精确控制
  - GET /client/home, /works, /featured-works, /works/:id, /works/:id/comments → 无需认证
  - POST/DELETE + GET favorites/likes/beauty-archive → `@UseGuards(ClientJwtAuthGuard)`
  - 无认证时 `@Req() request?:` 为 undefined，调用 Service 公开方法
- **ClientHomeService**：新增 5 个公开方法 `getHomePublic/getWorksPublic/getWorkPublic/getCommentsPublic/getFeaturedWorksPublic`

## 前端修复
- **app.js onLaunch**：跳转前调用 `verifyToken()` 轻量校验 token
  - 401 → `clearInvalidAuth()` 清除所有 Storage 登录态，回退登录页
  - 网络错误 → 保守策略，不清除 token 仍跳转
