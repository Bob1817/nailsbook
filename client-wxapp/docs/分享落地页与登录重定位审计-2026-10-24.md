# 分享落地页与登录重定位审计

- 日期：2026-10-24
- 范围：微信小程序 `client-wxapp/`
- 目标：分享页可匿名浏览、任何入口都可退出；账户操作能恢复登录前上下文；受保护页面不跨角色读取数据。

## 结论

本轮将页面分成“匿名可浏览入口”和“必须登录的业务页”，统一了返回、登录恢复和角色重定位规则。公开分享页不再依赖页面栈，也不会因为设备上残留过期登录态而强制中断浏览。受保护请求继续由请求层校验账户角色，并由后端校验资源归属；会话失效时保留原页面及参数，登录后只恢复与当前账户角色相符的页面。

## 页面分级

| 页面 | 匿名能力 | 必要参数 | 账户操作 |
| --- | --- | --- | --- |
| 美甲师主页 `artist-home` | 查看主页、店铺和公开作品 | `id` | 预约、联系时登录并返回原页 |
| 公开作品 `public-work` | 查看分享作品 | `shareToken`、`id` 或分享场景值 | 预约同款、联系时登录并返回原页 |
| 快速预约入口 `quick-booking` | 查看美甲师和是否可约 | `techId` + `invite` | 进入选时页后按客户身份登录 |
| 报价确认 `quote-confirm` | 查看有效报价 | `token` | 接受报价、继续预约时按客户身份登录 |
| 到店指引 `shop-guidance` | 查看门店指引 | `techId` | 无强制登录操作 |
| 美甲师公开画册 `works` | 仅 `techId` 模式可匿名查看 | `techId` | 预约时登录并返回原页 |

普通客户作品列表不属于公开内容。未指定 `techId` 时不再开放分享；分享数据尚未准备好时统一回退到客户首页，避免把私有页面或需要登录的列表发给访客。

## 统一交互逻辑

1. 从聊天、朋友圈、二维码或历史会话进入时，先按路由判断页面是否允许匿名查看。
2. 匿名页直接读取公开接口。设备上若只有过期登录态，清理失效会话并继续按游客浏览。
3. 页面顶部返回：存在上一页时正常返回；页面栈只有一层时，根据有效账户进入美甲师工作台或客户首页。
4. 公开页加载失败或内容为空时，保留“重新加载”，并提供“进入小程序首页”，不再形成无出口页面。
5. 用户触发预约、联系、收藏等账户操作时，记录当前完整业务地址，再进入登录或注册。
6. 登录成功后校验账户角色：
   - 客户恢复客户业务页或原公开页；
   - 美甲师恢复美甲师业务页或原公开页；
   - 客户打开美甲师私有页、美甲师打开客户私有页时，重定位到本人首页；
   - 客户预约入口在美甲师身份登录后转为美甲师代客建单入口。
7. 受保护 API 在请求前校验令牌所属角色；订单、客户、作品等具体资源归属仍由后端授权校验决定，前端不以 URL 参数推断权限。

## 已修复问题

| 优先级 | 问题 | 处理结果 |
| --- | --- | --- |
| P0 | 分享页单页栈的返回按钮无效 | 通用导航增加单页栈首页兜底 |
| P0 | 会话过期跳登录时丢失原页面 | 保存完整路由和查询参数，登录后按角色恢复 |
| P0 | 过期会话会阻断匿名分享页 | 公开入口降级为游客继续浏览 |
| P0 | 分享失败时可能发出私有页面 | 订单、快捷报价、作品详情统一回退客户首页 |
| P1 | 公开页面加载失败后只能反复重试 | 美甲师主页、快速预约、到店指引、作品页增加首页出口 |
| P1 | 普通客户作品列表可被误分享 | 无美甲师上下文时关闭分享，并使用安全回退路径 |
| P1 | 到店指引未纳入启动页保护 | 已加入分享落地页保留清单 |
| P1 | 登录后可能恢复到错误角色页面 | 登录后路由统一按角色和页面类型重定位 |

## 验证结果

### 自动化

- 小程序静态检查：5 个主包页面、74 个分包页面、257 个 JavaScript 文件、120 个 JSON 文件通过。
- 新增分享入口专项门禁：覆盖单页栈出口、过期会话恢复、角色重定位、公开入口清单和私有分享回退。
- 会话过期测试：并发 401 只刷新和清理一次；网络故障不误退出；原页面参数可恢复。
- 完整发布门禁：1 项全量静态检查、89 项专项检查全部通过。

### 开发者工具

- 使用“美甲师主页布局”独立编译场景打开公开页，未登录状态可以读取主页、门店和公开作品。
- 页面栈只有一层时点击顶部返回，成功退出分享页。
- 本地残留会话失效后展示统一登录过期提示和登录入口，不再停留在原分享页。
- 开发者工具代码质量面板显示“未发现代码质量问题”。

## 人工验收清单

1. 清除开发者工具缓存和登录态，分别从六类公开路径进入，确认内容可查看。
2. 在每个公开页直接点击顶部返回，确认进入客户首页；有效美甲师登录态应进入美甲师首页。
3. 对每个公开页制造断网或无效参数，确认可“重新加载”或“进入小程序首页”。
4. 从公开作品、主页、快速预约和报价确认发起账户操作，完成登录或注册后确认返回原业务内容。
5. 用客户账号打开美甲师私有路径、用美甲师账号打开客户私有路径，确认进入本人首页且没有发出跨角色 API 请求。
6. 让登录态自然过期后从分享卡片进入公开页，确认仍可浏览；再执行预约操作，确认登录后回到原页。
7. 用无权限账户打开他人的订单、客户或非公开作品链接，确认服务端返回无权限或资源不存在，页面不展示数据。

## 后续约束

新增可分享页面时，必须同时登记匿名数据接口、有效参数、账户操作登录回跳、单页栈首页出口和错误态出口，并加入 `test-share-entry-navigation.js`。新增受保护页面时，API 路径必须带明确的 `/api/client/` 或 `/api/technician/` 身份前缀，资源归属由服务端校验。
