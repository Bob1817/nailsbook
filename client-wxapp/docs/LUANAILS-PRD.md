# luanails 产品需求文档

版本：MVP 1.0
更新日期：2026-07-29
状态：开发基线

## 1. 产品定义

luanails 是面向自由美甲师的个人商业经营系统。产品帮助美甲师沉淀自己的客户资产、提高预约和服务效率、通过老客户推荐获得新客户，并通过经营数据持续改善收入和复购。

luanails 不是美甲交易撮合平台、门店经营平台、美甲师招聘平台或多级分销平台。平台不以订单抽佣为主要商业模式，不拥有美甲师的客户关系。

一句话定义：

> luanails 通过客户资产管理、预约管理、单层推荐增长和经营分析，帮助自由美甲师从个人手艺人成长为个人品牌经营者。

## 2. 目标用户

### 2.1 核心用户：自由美甲师

典型特征：

- 以个人身份提供上门或到店美甲服务。
- 通过微信、朋友圈和熟人推荐获客。
- 使用聊天、表格或手工方式维护预约和客户。
- 希望客户关系属于自己，而不是门店或平台。

核心任务：

- 管理客户、预约、服务和作品。
- 知道今天应该服务谁、联系谁。
- 知道哪些客户即将复购或正在流失。
- 让满意客户持续带来新客户。
- 了解收入、客户质量和经营趋势。

### 2.2 服务用户：美甲客户

核心任务：

- 查看专属美甲师的服务、作品和可预约时间。
- 在线预约、沟通、确认报价并查看服务记录。
- 保存自己的美甲档案和照片。
- 推荐好友并获得可用于后续消费的美甲基金。

### 2.3 后续用户

- 合作空间运营者：MVP 后建设。
- 个人品牌主理人及合作美甲师：工作室版建设。

## 3. 产品原则

1. 客户属于美甲师。平台帮助美甲师管理客户，不将客户转化为平台公共流量。
2. 预约是服务履约底座，不是交易抽佣入口。
3. 推荐只允许单层归因，不产生跨层级收益。
4. 奖励以美甲基金或消费权益呈现，主要用于促进复购。
5. 经营指标必须可解释、可下钻、可复算。
6. 保留现有预约、作品、档案、授权、聊天和服务配置，不做破坏性重构。
7. 手机是客户和美甲师的主要工作设备，关键操作必须适合单手触控。

## 4. MVP 目标与成功指标

### 4.1 MVP 目标

验证一个核心闭环：

`美甲师建立经营主页 → 邀请客户绑定 → 客户预约 → 完成服务 → 沉淀客户和收入 → 客户推荐好友 → 好友完成首单 → 推荐人获得美甲基金 → 基金促进复购`

### 4.2 MVP 产品成功指标

首期上线后按美甲师维度统计：

- 至少 80% 的有效预约可以完整走到完成或正常取消。
- 订单完成后，客户档案、收入和服务记录保持一致。
- 美甲师能够识别本月新客、复购客和待复购客户。
- 推荐关系可从分享入口追踪到被推荐客户的有效首单。
- 所有美甲基金变动均能追溯到订单和推荐关系。
- 不产生二级及以上推荐奖励。

具体业务目标值由真实试点数据确定，MVP 不预设虚假增长目标。

## 5. MVP 范围

### 5.1 经营主页与客户绑定

保留现有美甲师资料、服务项目、服务方式、作品、邀请码和分享能力，并将其统一表达为美甲师个人经营主页。

需求：

- 客户通过美甲师邀请码、名片或分享链接进入。
- 注册或登录后与来源美甲师建立绑定。
- 支持绑定多位美甲师和设置默认美甲师。
- 分享入口必须携带来源标识，登录后不能丢失归因。
- 全平台作品发现保留为辅助入口，不作为 MVP 核心获客模式。

账号与登录要求：

- 微信小程序支持微信授权登录，已绑定账号通过 OpenID 一键登录。
- 登录页同时展示“微信授权登录”和“手机号登录”切换项，只预检测微信绑定状态，不得在用户未选择登录方式时自动跳转；两种方式可随时切换。
- 用户主动授权微信手机号后，系统可以创建新账号或合并已有手机号账号；拒绝授权时仍可使用手机号密码登录。
- 新客户必须通过有效美甲师邀请完成首次注册和绑定，不能因微信授权绕过来源关系。
- 美甲师微信登录只能绑定已有美甲师账号，或结合有效管理员邀请密钥完成受控入驻。
- 同一微信身份可以同时具备客户和美甲师角色，但两个角色的 Token 和接口权限保持隔离。
- 密码作为备用登录方式；忘记密码和首次设置密码必须通过对应场景的短信验证码。

### 5.2 客户资产管理

客户档案需要包含：

- 姓名、电话、头像、地址、生日、标签和备注。
- 首次服务、最近服务、累计完成服务次数。
- 累计消费、平均客单价。
- 平均服务周期和预计下次服务日期。
- 客户来源。
- 生命周期：新客、活跃、待复购、沉睡。
- 历史预约、收入、评价、客户照片和关联作品。

规则：

- 人工标签与系统生命周期分开存储和展示。
- 生命周期必须根据明确规则计算，并允许解释原因。
- 客户只能被其绑定且有权限的美甲师查看。
- 指标优先从订单和收入聚合，MVP 不重复存储可可靠计算的数据。

### 5.3 预约与时间管理

保留现有预约状态机，并完善：

- 客户选择服务、美甲师、日期、时段和服务方式。
- 到店地址和上门地址。
- 美甲师报价，客户接受或拒绝。
- 报价确认后支付定金，服务完成后支付剩余订单款。
- 支付状态、预约确认、开始服务、完成和取消。
- 工作时间、休息日和临时不可预约时间。
- 服务端冲突检测。
- 改期或取消后释放时段。
- 预约前一天和前一小时提醒。
- 弱网和重复提交保护。

规则：

- 预约冲突必须由服务端最终判断。
- 已完成、已取消等终态不得非法回退。
- 收入仅在订单完成后确认。
- 定金和尾款必须分别形成支付单，不以客户端按钮直接改写已支付状态。
- 营业执照和微信商户资质完成前，支付单可创建但微信渠道保持待开通；不得模拟生产支付成功。

### 5.4 单层推荐增长

需求：

- 已绑定客户可以生成专属推荐链接。
- 新客户打开链接后记录推荐来源。
- 新客户注册并绑定对应美甲师后建立直接推荐关系。
- 被推荐客户的首个有效订单完成后，推荐人获得美甲基金。
- 美甲师和客户均可查看推荐状态。

规则：

- A 推荐 B、B 推荐 C 时，A 不因 C 获得奖励。
- 每位被推荐客户在同一美甲师下只能有一个有效推荐人。
- 推荐关系一旦由有效注册确认，不能被普通分享链接覆盖。
- 自我推荐、重复账号和异常订单不产生奖励。
- MVP 仅支持“首个有效完成订单”触发一次奖励。

### 5.5 美甲基金

需求：

- 客户查看可用、待生效和已使用基金。
- 订单完成后发放奖励。
- 客户下次预约确认报价时可选择抵扣。
- 取消、退款或异常订单支持冲正。
- 每笔变动展示来源、时间、金额和状态。

规则：

- 余额必须由不可变账本汇总，不能直接修改余额而不留记录。
- 同一触发订单只能发放一次。
- 抵扣金额不得超过可用余额或订单允许抵扣上限。
- 邀请奖励统一为首个有效订单实付金额的 5%，精确到分。
- MVP 不支持提现、转账、跨美甲师使用和多级分销。

### 5.6 经营数据

MVP 指标：

- 今日预约、待处理预约、本月完成订单。
- 总客户、本月新客、活跃客户、待复购客户。
- 本月确认收入、平均客单价。
- 复购客户数和复购率。
- 推荐人数、有效推荐人数、推荐成交收入。
- 美甲基金发放和抵扣金额。

指标定义：

- 新客：统计周期内首次建立客户档案的客户。
- 完成客户：至少有一笔完成订单的客户。
- 复购客户：累计完成订单不少于两笔的客户。
- 复购率：复购客户数 ÷ 完成客户数；分母为零时返回空值。
- 平均客单价：确认收入 ÷ 对应确认收入订单数。
- 待复购：距离最近完成服务达到个人平均服务周期；数据不足时采用可配置默认周期。

### 5.7 作品和美甲档案

以下现有能力继续保留：

- 作品发布、编辑、上下架、置顶和精选。
- 公开作品与客户专属作品。
- 查看、分享、收藏、点赞和评论授权。
- 服务记录、客户照片、美甲师作品和评价。
- 预约同款、美照海报和分享文案。

在新定位下，它们承担个人品牌表达、服务记录和推荐传播素材的作用，而不是平台内容增长本身。

### 5.8 订阅

MVP 套餐方向：

- 免费版：基础客户管理、预约和服务记录。
- 专业版：客户分群、经营分析、推荐增长和高级展示。
- 工作室版：MVP 后提供团队、客户分配和团队经营。

MVP 需要完成套餐展示、免费版自动兜底、服务端功能权限判断、额度判断和到期降级。订阅支付复用统一支付单；微信商户资质完成前仅允许提交升级意向或由管理员开通，不模拟线上支付成功。自动续费和工作室能力后置。

### 5.9 支付与结算

- 订单支付拆分为定金和尾款两类支付单。
- 客户接受报价时选择本美甲师名下的美甲基金，基金先从订单总应付中抵扣。
- 定金现金应付不超过抵扣后的订单现金应付；尾款为剩余未支付金额。
- 支付单金额以“分”为单位保存，订单展示金额可使用元。
- 支付单必须有唯一业务幂等键，重复点击或重复回调不能重复入账。
- 微信支付成功只能由验签后的服务端回调确认；客户端支付结果仅用于刷新状态。
- 订单取消、退款或支付失败时保留原支付记录，并使用退款/冲正记录处理，不删除流水。

## 6. MVP 外范围

- 平台订单抽佣和统一资金结算。
- 多级分销、提现和客户间转账。
- 公共流量竞价、排名或平台派单。
- 合作空间完整网络及场地结算。
- 多美甲师团队、客户分配和团队收益。
- 自动定价、不可解释的 AI 经营建议。
- 真实 AI 图片生成。

## 7. 核心用户故事

### 美甲师

- 作为美甲师，我希望看到待复购客户，以便主动联系而不是翻聊天记录。
- 作为美甲师，我希望客户自己选择可约时间，以减少反复沟通。
- 作为美甲师，我希望知道客户来自谁的推荐，以衡量口碑增长。
- 作为美甲师，我希望每笔收入和基金成本可追溯，以了解真实经营结果。

### 客户

- 作为客户，我希望快速预约熟悉的美甲师，不必重复询问档期。
- 作为客户，我希望保留自己的美甲记录和照片。
- 作为客户，我希望推荐朋友成功消费后获得明确的消费权益。
- 作为客户，我希望随时知道基金为什么增加、在哪里使用。

## 8. 核心验收场景

1. 美甲师完成个人资料、服务和可预约时间设置。
2. 老客户通过邀请码绑定美甲师并完成一次预约。
3. 美甲师完成订单后，收入、服务档案和客户经营指标同步更新。
4. 老客户分享专属推荐链接，新客户完成注册和绑定。
5. 新客户完成首个有效订单，老客户基金只发放一次。
6. 老客户下一单使用基金，账本同时记录抵扣。
7. 订单取消或冲正后，错误奖励不再计入可用余额。
8. B 推荐 C 不会让 A 获得任何 C 相关奖励。

## 9. 发布门槛

- 后端核心测试通过。
- 微信开发者工具问题面板为零。
- iOS 和 Android 至少各完成一次核心预约真机流程。
- 双账号完成绑定、预约、完成、推荐、奖励和抵扣测试。
- 指标抽样结果与订单、收入和账本明细一致。
- 未授权客户不能查看其他客户资料、专属作品或基金。
