# NailBook 小程序 UI 设计规范与准则

本文档基于角色选择页、美甲师登录页、美甲师邀请注册页的最新优化结果整理，用于约束后续微信小程序页面设计与实现。优先级：移动端首屏体验、触控友好、信息层级清晰、风格一致。

## 1. 产品气质

NailBook 是面向客户和美甲师的美甲预约小程序。界面应当轻盈、干净、柔和，但不能牺牲表单效率。客户侧偏消费体验，美甲师侧偏工作管理，两端都应优先适配手机。

关键词：

- 柔和粉色 + 紫色点缀
- 白底、浅背景、轻阴影
- 清晰标题层级
- 紧凑但不拥挤的移动端表单
- 明确的点击反馈与错误反馈

## 2. 移动端优先原则

所有页面先按手机竖屏设计，再向更大屏幕扩展。

- 首屏优先展示核心内容和主操作。
- 登录、注册、选择身份等入口页应尽量一屏完成，不依赖上下滑动。
- 交互控件最小触控高度为 `88rpx`，文字链接最小点击行高为 `44rpx`。
- 固定导航和底部区域必须考虑安全区，不让内容被胶囊按钮或手势条遮挡。
- 页面横向内边距建议为 `40rpx` 到 `48rpx`。
- 表单页不要使用大面积装饰图或过高品牌区挤占输入区域。

## 3. 颜色规范

### 主色

- 品牌粉：`#ff6b8a`
- 品牌浅粉：`#ff8fa3`
- 品牌紫：`#8b5cf6`
- 辅助蓝紫：`#667eea`

### 背景

入口页背景使用浅粉到白色再到浅灰的纵向渐变：

```css
background: linear-gradient(180deg, #fff8fb 0%, #ffffff 34%, #f8f9fc 100%);
```

### 文本

- 主标题：`#1f2937`
- 正文/标签：`#374151`
- 辅助说明：`#6b7280`
- 弱化文本：`#9ca3af`
- 错误提示：`#dc2626`

### 使用规则

- 粉色用于客户、品牌、主要动作。
- 紫色用于美甲师、强调动作、渐变终点。
- 错误状态必须使用红色边框加错误文案，不能只靠颜色变化。
- 不使用大面积高饱和背景。

## 4. 标题与导航

页面标题必须分工清楚，避免顶部导航标题与页面内标题重复。

### 顶部导航

- 顶部导航用于表达模块或产品位置，如 `NailBook`、`美甲师端`。
- 不需要副标题时必须显式设置 `subtitle=""`，避免默认显示 `NailArt`。
- 入口页可使用透明导航：`<nav-bar title="NailBook" subtitle="" transparent/>`。

### 页面内标题

- 页面内标题表达当前任务，如 `选择身份`、`登录`、`邀请注册`。
- 注册页标题应短，辅助说明放在副标题或提示条中。
- 不要同时出现两个含义接近的大标题，例如顶部 `登录` + 页面 `美甲师登录`。

## 5. 页面结构模式

### 入口页

适用于角色选择页、登录页、注册页。

推荐结构：

1. 顶部导航：轻量展示产品或端类型。
2. 页面标题区：短标题 + 一句辅助说明。
3. 主内容区：角色卡或表单。
4. 底部链接：协议、返回入口、次要动作。

空间控制：

- 品牌图标不超过 `104rpx`。
- 标题区和主内容区间距控制在 `18rpx` 到 `56rpx`。
- 一屏页不得使用过高头图、插画或大面积空白。

### 工作/管理页

工作页可以信息密度更高，但仍应保持：

- 主要状态在首屏可见。
- 列表项有清晰主次信息。
- 关键操作按钮固定或靠近相关内容。
- 不把页面分成过多装饰卡片。

## 6. 角色卡规范

角色选择页的角色卡作为入口卡片基准。

推荐尺寸：

- 卡片最小高度：`136rpx`
- 圆角：`18rpx`
- 内边距：`24rpx 26rpx`
- 图标尺寸：`76rpx`
- 卡片间距：`18rpx`

视觉：

- 背景：`#ffffff`
- 边框：`2rpx solid rgba(255, 107, 138, 0.08)`
- 阴影：`0 10rpx 26rpx rgba(15, 23, 42, 0.05)`
- 客户图标使用粉色渐变。
- 美甲师图标使用紫色/蓝紫渐变。

交互：

- 整张卡片可点击。
- 右侧用箭头表达可进入。
- 文案需要说明进入后的主要任务，例如“浏览作品、预约美甲服务”。

## 7. 表单规范

表单是本小程序的关键体验，必须优先清晰和高效。

### 输入框

推荐基础样式：

```css
min-height: 88rpx;
background-color: #f9fafb;
border: 2rpx solid transparent;
border-radius: 14rpx;
padding: 0 26rpx;
font-size: 28rpx;
color: #1f2937;
box-sizing: border-box;
```

聚焦状态：

```css
background-color: #ffffff;
border-color: #ff6b8a;
```

错误状态：

```css
border-color: #dc2626;
background-color: #ffffff;
```

### 标签与辅助文案

- 每个输入框必须有可见标签。
- 标签字号建议 `24rpx` 到 `26rpx`。
- 复杂字段需要辅助文案，例如邀请码、密码规则。
- 辅助文案放在输入框下方，字号建议 `21rpx` 到 `23rpx`。

### 手机号与次要动作

注册页手机号已确定时，使用只读行展示。

- 只读手机号高度可压缩到 `72rpx`。
- “换个手机号”放在手机号标签右侧，不放到底部。
- 次要动作最小点击行高为 `44rpx`。

## 8. 按钮与链接

### 主按钮

推荐样式：

```css
height: 88rpx;
background: linear-gradient(135deg, #ff6b8a, #8b5cf6);
color: #ffffff;
border-radius: 48rpx;
font-size: 30rpx;
font-weight: 500;
```

规则：

- 每个表单页只保留一个主按钮。
- loading 时禁用按钮并更换文案，例如 `检查中...`、`注册中...`。
- 禁用状态使用 `opacity: 0.5`。
- 去掉微信 button 默认边框：`.btn-primary::after { border: none; }`。

### 链接

- 次要链接使用品牌粉：`#ff6b8a`。
- 底部返回或协议文案使用弱化色：`#9ca3af`。
- 链接不应挤占主按钮位置，能合并到相关字段旁边时优先合并。

## 9. 邀请注册页准则

美甲师未注册时进入邀请注册页。该页的核心信息是“必须有邀请密钥才能注册”。

布局顺序：

1. 页面标题：`邀请注册`
2. 副标题：手机号尚未注册，需要有效邀请密钥
3. 邀请提示条
4. 邀请密钥输入框
5. 手机号只读行 + 换个手机号
6. 姓名
7. 设置密码
8. 确认密码
9. 注册并登录
10. 返回选择身份

规则：

- 邀请密钥必须放在手机号前面，作为页面第一输入项。
- 提示条保持单行或短双行，不能占用过多首屏空间。
- 不显示大品牌图标，避免挤压表单。
- 尽量一屏展示所有字段和操作。

## 10. 一屏布局密度

登录、注册、选择身份页应优先满足一屏操作。

压缩优先级：

1. 减少品牌图标和标题区高度。
2. 合并相关次要动作，例如把“换个手机号”放到手机号字段右侧。
3. 缩短提示文案。
4. 减少表单项间距。
5. 保留输入框和主按钮触控高度。

不能压缩的内容：

- 主按钮触控高度。
- 输入框可读性。
- 错误提示位置。
- 表单字段标签。

## 11. 文案准则

文案应短、明确、直接服务当前任务。

推荐：

- `请选择登录身份`
- `邀请注册`
- `请输入平台提供的 16 位邀请密钥`
- `注册并登录`
- `换个手机号`

避免：

- 大段说明文字。
- 同一屏重复表达同一含义。
- 使用“温馨提示”等低信息量标题。
- 使用不明确的按钮文案，如“提交”“确定”。

## 12. 禁用模式

后续页面应避免以下模式：

- 大图标 + 大标题 + 大空白同时出现，导致首屏主操作下移。
- 顶部导航标题和页面标题重复。
- 只使用 placeholder，不显示字段标签。
- 错误只用 toast，不在字段附近反馈。
- 入口页使用深色背景或高饱和大面积渐变。
- 卡片层层嵌套。
- 触控控件低于 `88rpx`，文字链接低于 `44rpx` 点击行高。
- 为了装饰加入无业务意义的图形、光斑、复杂插画。

## 13. 实施检查清单

提交 UI 页面前逐项检查：

- [ ] 是否以手机竖屏为第一设计目标？
- [ ] 首屏是否能看到核心内容和主操作？
- [ ] 顶部导航和页面标题是否不重复？
- [ ] 输入框、按钮、卡片是否满足触控高度？
- [ ] 每个输入框是否有可见标签？
- [ ] 错误是否在相关字段附近显示？
- [ ] 主按钮是否只有一个？
- [ ] 次要动作是否放在最相关的位置？
- [ ] 背景、圆角、阴影、颜色是否与登录/注册/选择身份页一致？
- [ ] 是否避免了无关重构和额外装饰？
