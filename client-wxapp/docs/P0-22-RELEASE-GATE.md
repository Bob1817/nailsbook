## 部署

1. 冻结发布分支，记录分支、SHA、数据库和上传资源备份校验值。
2. 在生产数据库副本执行 `npx prisma migrate deploy`，完成数据抽样与公开字段检查。
3. 部署后端并检查健康接口、日志、公开主页、限流和鉴权。
4. 上传小程序体验版，完成上表双端验收；审核通过后再发布正式版。
5. 发布后跑通公开主页 → 咨询 → 预约申请的生产冒烟，观察错误率和重复事件。

## 回滚

1. 停止新版本流量或回退后端镜像/进程至发布前 SHA。
2. 若仅应用异常且迁移向后兼容，保留数据库，回退代码和小程序版本。
3. 若发生数据破坏，停止写入，将当前故障库与上传目录单独留档，再恢复发布前数据库及上传资源备份。
4. 恢复后验证登录、公开主页、咨询、预约、订单完成和收入一致性。
5. 记录故障窗口内的咨询、预约和支付写入，人工核对并补偿后再恢复发布。

SQLite 迁移不做手写逆向 SQL；涉及结构或数据破坏时使用已校验备份恢复，避免不完整回滚。
