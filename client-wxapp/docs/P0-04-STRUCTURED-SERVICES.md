# P0-04 服务项目结构化

## 实现口径

- `Service` 是服务名称、说明、时长、价格、可预约状态、排序和归档状态的正式数据源。
- 金额在数据库中统一使用整数分（`priceMinFen` / `priceMaxFen`），接口为兼容现有小程序仍使用元。
- 固定价的最低价和最高价相同；区间价要求最高价不小于最低价。
- 归档是软删除：设置 `archivedAt` 并关闭可预约状态，不删除服务记录。
- `Order.serviceId` 和 `NailWork.serviceId` 保留正式服务关系；历史展示字段仍保留，归档不影响历史数据。
- `Technician.serviceItems` 保留为过渡期兼容镜像，新增、修改、上下架和归档后由服务端同步，不再由页面写死。

## 迁移与兼容

- 迁移 `20260812233000_add_structured_services` 使用 SQLite JSON1 将现有 `serviceItems` 拆分为正式记录。
- 旧 `id` 保留为 `publicId`，旧客户端可继续提交 `selectedServiceIds`。
- `publicId` 按美甲师范围唯一，允许不同美甲师使用相同的历史默认 ID。
- 对迁移前新写入的旧 JSON 数据，客户端下单时会先补齐正式服务记录，再建立预约关联。

## 验收记录

- Prisma schema 格式化和校验通过。
- 空库顺序执行全部 SQL 迁移后，`integrity_check = ok`。
- 历史库模拟迁移通过：固定价 `128.88` 迁移为 `12888` 分，区间价 `199-399` 迁移为 `19900-39900` 分，上下架状态保留。
- 迁移后数据库与 Prisma schema 对比无差异，外键检查无异常。
- 后端构建通过；64 个测试套件、268 个测试用例全部通过。
- 小程序服务页和作品编辑页 JavaScript 语法检查通过，现有静态检查脚本全部通过。

## 回滚

1. 回滚应用到 P0-04 之前的版本，旧接口仍从 `Technician.serviceItems` 读取兼容镜像。
2. 恢复迁移前数据库备份；不建议在有新预约或作品关联后直接删除 `Service` 表。
3. 如只回滚前端，保留新表和兼容镜像即可，不需要做数据库逆向迁移。
