# luanails MVP 开发任务与优先级

更新日期：2026-07-29
产品基线：[LUANAILS-PRD.md](./LUANAILS-PRD.md)
技术基线：[LUANAILS-TECHNICAL-DESIGN.md](./LUANAILS-TECHNICAL-DESIGN.md)

## 1. 优先级定义

- P0：没有完成就不能安全发布或无法形成基础服务闭环。
- P1：验证“管理并增长客户资产”必须具备的 MVP 能力。
- P2：提高经营效率和产品完整度，核心 MVP 稳定后建设。
- P3：产品扩展方向，不纳入首个 MVP。

状态：

- `[ ]` 待开发
- `[-]` 进行中或已开发待生产验收
- `[x]` 已通过代码和业务验收

## 2. P0：发布与数据可信底座

### P0-01 冻结产品和指标口径

- [x] 更新产品定位、MVP 范围和非目标。
- [x] 更新增量技术方案。
- [x] 定义新客、完成客户、复购客户、复购率和平均客单价。
- [ ] 产品、研发和试点美甲师确认推荐资格与基金规则。

验收：所有页面、接口和报表使用同一指标定义。

### P0-02 完成现有双端核心回归

- [-] 客户和美甲师登录、注册、找回密码、角色切换。
- [-] 邀请码注册、绑定、解绑和默认美甲师。
- [-] 创建、报价、客户确认、定金确认、服务、完成和取消。
- [-] 作品权限、私密分享和撤销授权。
- [-] 双端文字、图片、预约卡片和已读消息。
- [-] iOS/Android 图片、相册、位置和安全区。

验收：双账号可以在生产候选环境完整完成一次服务；非法状态被服务端拒绝。

### P0-03 预约冲突和幂等

- [-] 服务端创建预约时检查美甲师已有预约和 blocked slot。
- [x] 客户和美甲师更新预约时间时执行相同冲突检查，并同步占用时段。
- [x] 当前单实例 SQLite 部署按美甲师串行处理档期写入，并由事务复查冲突；多实例部署前需升级数据库级锁方案。
- [-] 客户端主要动作防重复提交。
- [x] 完成和取消通过条件状态更新抢占流转权，订单收入由 `orderId` 唯一约束防止重复入账。
- [ ] 推荐奖励触发具备唯一业务来源和幂等键。
- [x] 修改预约时间后重置原预约提醒发送状态。

验收：同一美甲师重叠时段不能生成两笔有效预约；重复请求不会重复改变状态。

### P0-04 统一经营概览

- [x] 新增美甲师经营概览服务端接口。
- [x] 统一本月确认收入、平均客单价和复购率口径。
- [x] 增加美甲师数据隔离和零数据测试。
- [x] 小程序经营概览优先使用服务端指标，失败时兼容现有展示。
- [ ] 使用生产副本抽样核对指标。

验收：接口结果可从订单、收入、客户和评价明细复算，前端不依赖分页列表计算关键指标。

### P0-05 发布候选版本

- [x] 盘点现有未提交改动、候选范围和排除范围。
- [x] 在临时空数据库验证 26 个迁移、schema 零差异、外键和完整性。
- [x] 全量后端 32 个测试套件、156 项测试和构建通过。
- [x] 小程序 59 个页面、JS/JSON 和事件绑定静态检查通过。
- [x] 形成 RC1 版本说明、部署步骤和回滚说明。
- [ ] 创建只包含候选范围的冻结提交并记录 SHA。
- [x] 微信开发者工具问题面板为零；重置文件系统状态并重新打开项目后普通编译通过，延迟观察期间未复现 `6000100 unbind download url`。
- [ ] 完成双账号和 iOS/Android 真机冒烟。

验收：可从干净环境部署，核心流程有明确回滚路径；冻结提交和人工门槛全部完成。

## 3. P1：客户资产 MVP

### P1-01 客户经营指标

- [ ] 客户详情返回首次服务、最近服务和完成服务次数。
- [ ] 返回累计确认消费和平均客单价。
- [ ] 计算平均服务周期和预计下次服务日期。
- [ ] 明确数据不足时的默认周期。
- [ ] 客户详情移动端展示经营摘要。

验收：任一金额和次数可以下钻到原始订单或收入。

### P1-02 客户生命周期

- [ ] 实现新客、活跃、待复购和沉睡规则。
- [ ] 客户列表支持系统生命周期筛选。
- [ ] 人工标签与系统状态分开展示。
- [ ] 展示生命周期原因和预计复购日期。

验收：固定测试数据下分群结果稳定且可解释。

### P1-03 客户来源和跟进

- [ ] 增加客户来源字段并兼容历史客户。
- [ ] 增加客户跟进记录。
- [ ] 增加计划跟进时间和完成状态。
- [ ] 美甲师首页展示今日客户跟进任务。

验收：美甲师可以创建、完成并追溯一次客户跟进。

### P1-04 预约提醒

- [ ] 核实前一天和前一小时定时任务。
- [ ] 接入实际可用的订阅消息或推送通道。
- [ ] 保存发送成功、失败和重试状态。
- [ ] 改期、取消后更新或停止原提醒。

验收：提醒只发送一次，取消订单不继续发送服务提醒。

## 4. P1：推荐增长 MVP

### P1-05 推荐活动配置

- [ ] 美甲师配置奖励值、最低订单金额、有效期和启停状态。
- [ ] 专业版功能权限由服务端校验。
- [ ] 未配置活动时分享仍可用，但不承诺奖励。

验收：活动关闭后不建立新的奖励资格，不影响已有预约。

### P1-06 单层推荐关系

- [ ] 客户生成不暴露身份的推荐链接。
- [ ] 未登录打开后安全保存来源并在登录后恢复。
- [ ] 注册和绑定时建立直接推荐关系。
- [ ] 数据库限制同一被推荐客户的重复归因。
- [ ] 拒绝自我推荐和覆盖有效关系。
- [ ] 客户和美甲师查看推荐状态。

验收：A→B→C 场景中只有 A→B 和 B→C 两条直接关系，不存在 A→C 收益。

### P1-07 推荐资格

- [ ] 被推荐客户完成首个有效订单后确认资格。
- [ ] 校验最低实付金额。
- [ ] 资格确认与订单完成在事务中执行。
- [ ] 重复完成或定时重试不重复确认。

验收：同一被推荐客户在同一美甲师下最多触发一次首单奖励。

### P1-08 美甲基金账本

- [ ] 创建基金账户和不可变账本。
- [ ] 支持待生效、可用、已使用、已过期和已冲正。
- [ ] 奖励发放具备唯一业务来源。
- [ ] 客户查看余额和明细。
- [ ] 美甲师查看基金成本。

验收：账户余额等于有效账本汇总，任一变动可追溯到订单。

### P1-09 基金抵扣与冲正

- [ ] 客户确认报价时选择抵扣。
- [ ] 服务端校验余额、上限和所属美甲师。
- [ ] 抵扣与订单金额更新保持事务一致。
- [ ] 取消或退款创建反向账本。
- [ ] 禁止提现、转账和跨美甲师使用。

验收：重复提交不重复扣减；取消后余额和账本都可解释。

## 5. P1：经营分析 MVP

### P1-10 经营总览页面

- [ ] 展示本月确认收入和平均客单价。
- [ ] 展示总客户、新客、完成客户和复购率。
- [ ] 展示待复购客户入口。
- [ ] 展示推荐人数、有效推荐和推荐收入。
- [ ] 展示基金发放和抵扣金额。

验收：每个卡片都有定义说明和明细入口。

### P1-11 趋势和经营提醒

- [ ] 客户增长、收入和订单按日/周趋势。
- [ ] 服务项目和时段表现。
- [ ] 待复购、沉睡和高价值客户提醒。
- [ ] 数据不足时不生成结论。

验收：提醒可跳转到对应客户或订单，说明触发原因。

## 6. P2：品牌、内容和订阅完善

### P2-01 个人经营主页

- [ ] 统一资料、服务、作品、地址、可约时间和预约入口。
- [ ] 分享名片携带美甲师来源。
- [ ] 降低公共发现页的平台撮合表达。
- [ ] 保留现有作品和预约同款能力。

### P2-02 现有美学资产闭环验收

- [-] 客户专属作品和多客户授权。
- [-] 私密分享令牌和撤销。
- [-] 美甲档案、照片、评价和推荐。
- [-] 美照海报、滤镜、裁剪、保存和分享。
- [ ] 完成全部真机和生产权限验收。

### P2-03 订阅功能门控

- [-] 套餐和订阅数据模型。
- [-] 小程序套餐展示和联系客服。
- [ ] 免费版、专业版功能矩阵。
- [ ] 服务端统一权限判断。
- [ ] 到期、降级和超限行为。

## 7. P3：MVP 后扩展

### P3-01 合作空间网络

- [ ] 独立空间、设施、地址和营业时间。
- [ ] 空间与美甲师合作关系。
- [ ] 空间不可用时段和预约选择。
- [ ] 不引入平台抽佣和场地结算。

### P3-02 工作室版

- [ ] 品牌/工作室和成员角色。
- [ ] 客户归属、授权和分配。
- [ ] 订单分配、转派和接受。
- [ ] 团队经营数据和收益记录。

### P3-03 高级分析

- [ ] 服务定价辅助。
- [ ] 容量和档期利用率分析。
- [ ] 客户流失预测。
- [ ] 所有建议必须可解释并允许关闭。

## 8. 推荐开发顺序

1. P0-02 至 P0-05：先形成可信、可发布的基础版本。
2. P1-01、P1-02：让客户资产可经营。
3. P1-05 至 P1-08：形成推荐和奖励闭环。
4. P1-09：基金抵扣和冲正。
5. P1-10、P1-11：将可靠数据转化为经营决策。
6. P2：强化个人品牌、已有内容资产和订阅。
7. P3：在 MVP 真实数据证明需求后扩展。
