# 页面内首次使用与接单准备引导

## 范围与原则

仅覆盖微信小程序与对应后端。注册后直接进入实际业务页面；旧 onboarding 路由保留为兼容跳转，不再展示阅读式三步说明。引导以真实操作和已保存的数据为依据，浏览页面、关闭提示不会计作资料完成。

## 客户流程

- 首次注册、首次设置密码或首次选择客户身份后，开启当前账号的页面提示，保留安全站内回跳。
- 首页提示浏览作品；作品列表及底部作品入口提示查看详情、收藏与预约；作品详情可直接点击“预约这款”，执行现有预约同款操作。
- 预约表单提示服务、门店、日期时间和需求；订单页提示查看进度与联系美甲师。
- 提示均在实际页面中，可以按页点击“知道了”。记录为 `context_guide_v1_client_<用户 ID>`，互不影响其他账号；普通登录不会重新开启提示。
- 预约尚未开放时显示通用状态，具体资料缺项只在美甲师端呈现。

## 美甲师流程

工作台及“我的”显示“开启接单之旅”清单。适用于新注册美甲师，也用于提醒已有账号补齐缺失资料。每项都能直达实际编辑页面，返回后重新获取后端状态。

| 顺序 | 任务 | 完成条件与操作入口 |
| --- | --- | --- |
| 1 | 完善店铺信息 | 开启到店服务，添加并启用有效地址；进入店铺管理。保留系统已有仅上门服务的兼容规则。 |
| 2 | 制定服务与价格 | 至少一项启用中的服务，有名称、非负价格、正数时长；进入服务管理。 |
| 3 | 完善美甲师主页 | 头像、主页名称、背景图、自我介绍齐全，并公开主页；进入主页设置。发布还须满足现有品牌主页规则，包括 Slogan、城市、服务区域、环境照片、卫生说明、取消规则及可预约服务。分享标题、封面默认使用主页名称和背景图。 |
| 4 | 上传代表作品 | 至少一个有封面、未归档、可见、审核通过且公开的作品；进入作品管理。待审核或仅指定客户可见的作品不计完成。 |
| 5 | 安排工作时间 | 当前启用方案包含有效工作日与正确的起止时间；进入“我的”并打开工作时间设置。 |

服务排在主页前，避免主页发布因没有可预约服务而受阻。各编辑页在表单附近解释具体要求，并提供返回工作台查看进度的入口。作品待审核时提示先完成其他项。

新注册美甲师默认暂停接单。五项齐全后只解锁“开启接单”按钮，须美甲师主动确认；不会自动开启。已接单且资料完整时清单隐藏。后续删除必填资料或撤下唯一有效作品后，预约入口与后端提交均重新拦截，清单再次提示缺项。

## 数据与失败状态

- `GET /technician/auth/me` 的 `bookingSetup` 返回五项完成情况、总进度、资料是否齐全及实际是否接单；登录响应同步提供此结构。
- `bookingReadiness` 统一服务于开启接单、公开主页预约状态及客户提交预约检查，后端阻止直接绕过小程序提交。
- 工作台加载失败显示重试，旧进度不能用于开启接单。页面返回重新加载；旧请求、卸载后的响应与其他账号响应不得覆盖当前状态。
- 开启接单和保存主页防止重复提交；图片上传期间不能保存。照片上传失败保留已上传照片。
- 主页读取失败时禁止覆盖保存；先保存个人资料，再发布主页，确保发布校验读取新头像。缺少公开必填项在当前页说明。
- 操作触控不低于 44px，使用项目颜色令牌与预约卡片操作规格；按钮显示加载、禁用和按压状态。

## 自动验收

- `node client-wxapp/scripts/release-gate.js`：含首次入口、账号隔离、逐页关闭、回跳、清单刷新、重复开启、加载失败、旧响应、路由、不可预约时间与主页保存链路测试。
- `backend/src/technicians/booking-setup.integration.spec.ts`：使用临时 SQLite 数据库，实际调用资料、服务、主页保存方法，验收 0 → 5 → 主动开启 → 撤下作品重新拦截；不访问线上数据。
- 后端就绪规则、客户订单创建、公开主页、预约页面契约与客户订单 HTTP 契约测试；后端构建。
- 微信开发者工具视觉验收使用临时项目和本地固定数据，与真实账号隔离。模拟器结果不等同于真机、线上部署或微信提审发布。
